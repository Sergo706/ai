Multi-stage workflows can run for minutes across dozens of LLM and web requests. If a worker restarts or a container is evicted halfway through round 3, re-running from scratch wastes both latency and API spend. `AgenticWorkflowLoop` exposes first-class checkpointing hooks that integrate seamlessly with the [Run System](/runs) or any custom key-value/SQL store.

## How checkpointing works

At every durable boundary (after `seeds`, after local batches, after each external round, and after `critic`), the loop invokes `onCheckpoint(snapshot)` with a JSON-serializable `WorkflowCheckpoint`:

```ts [WorkflowCheckpoint Shape]
interface WorkflowCheckpoint {
  completedStages: WorkflowStage[]; // Stages already finished — skipped on resume
  localSearches: number;            // Local budget already spent
  externalRounds: number;           // External budget already spent
  state: unknown;                   // WorkflowStateSnapshot (Maps/Sets flattened to arrays)
}
```

When you later pass that object back through `resumeFrom`, `AgenticWorkflowLoop` restores `WorkflowState` (including `evidenceSet`, `localItems`, `externalArtifacts`, `issuedIntents`, `exhaustedIntents`, `seenLocalIds`, `attemptedTargets`, and spent round counts) and skips every stage listed in `completedStages`.

## Wiring `onCheckpoint` and `resumeFrom`

The example below pairs `AgenticWorkflowLoop` with `runWorkflow()`, `checkpoint()`, `parseCheckpoint()`, and `saveCheckpoint()` from the [Run System](/runs/checkpoints-and-workflows):

```ts [src/durable-workflow.ts]
import {
  AgenticWorkflowLoop,
  checkpoint,
  getConfiguration,
  parseCheckpoint,
  runWorkflow,
  type WorkflowCheckpoint,
} from "@riavzon/ai";

const CHECKPOINT_SPEC = {
  version: 1,
  phases: ["seeds", "local", "external", "critic", "final"] as const,
};

export async function runDurableResearch(params: {
  runId?: string;
  resumeRunId?: string;
  userId: string;
  query: string;
  conversationId?: number;
}) {
  const log = getConfiguration().logger;

  return runWorkflow(
    {
      runId: params.runId,
      resumeRunId: params.resumeRunId,
      kind: "workflow",
      name: "research",
      query: params.query,
      userId: params.userId,
      conversationId: params.conversationId,
      input: { query: params.query },
    },
    async (ctx) => {
      // Load prior loop checkpoint if adopting an interrupted run
      const rawCheckpoint = await ctx.loadCheckpoint();
      const parsed = parseCheckpoint<
        WorkflowCheckpoint,
        (typeof CHECKPOINT_SPEC.phases)[number]
      >(rawCheckpoint, CHECKPOINT_SPEC);

      const loop = new AgenticWorkflowLoop({
        ...buildAdapters(params.query),
        name: "research",
        query: params.query,
        signal: ctx.leaseSignal,
        resumeFrom: parsed?.state,
        onProgress: ctx.emitProgress,
        onCheckpoint: (snapshot) => {
          const latestStage =
            snapshot.completedStages[snapshot.completedStages.length - 1] ?? "seeds";
          ctx.saveCheckpoint(
            checkpoint({
              phase: latestStage,
              state: snapshot,
              roundsDone: snapshot.externalRounds,
            }),
          );
        },
      });

      const result = await loop.run();
      return {
        source: result.source,
        isSufficient: result.isSufficient,
        stopReason: result.stopReason,
        missingSearchTerms: result.missingIntents,
        urls: [],
        data: result.report,
      };
    },
    log,
  );
}
```

## Working with `WorkflowState` directly

If you inspect or restore state outside the loop (for example in tests or a custom multi-step orchestrator), `WorkflowState` exposes `toCheckpoint()` and `restore()` directly:

```ts [src/state-snapshot.ts]
import { WorkflowState } from "@riavzon/ai";

const state = new WorkflowState<string, { url: string }>("initial query", budgets);
state.appendEvidence("Verified pricing paragraph");

// Serialize to plain JSON (Maps & Sets become entry/value arrays)
const snapshot = state.toCheckpoint();
const json = JSON.stringify(snapshot);

// Hydrate into a fresh state instance with current budgets
const resumed = new WorkflowState<string, { url: string }>("initial query", budgets);
resumed.restore(JSON.parse(json));
```

## Cancellation & `WorkflowAbortedError`

Pass an `AbortSignal` into `config.signal`. The loop checks `signal.aborted` between stages and forwards `signal` into every adapter via `context.signal`.

When aborted, `loop.run()` marks `state.markAborted()` (`stopReason: "aborted"`) and throws `WorkflowAbortedError`:

```ts [src/handle-abort.ts]
import { AgenticWorkflowLoop, WorkflowAbortedError } from "@riavzon/ai";

try {
  const result = await new AgenticWorkflowLoop(config).run();
  console.log("Completed:", result.stopReason);
} catch (err) {
  if (err instanceof WorkflowAbortedError) {
    console.log("Workflow cancelled cleanly");
  } else {
    throw err;
  }
}
```

::note
Because `onCheckpoint` fires after every completed stage and external round, an aborted or crashed run retains all evidence gathered before cancellation. If you later retry or adopt the run, `resumeFrom` picks up immediately without redoing completed stages. For the full production setup (`boot` → `registerRunResumer()` → runner → HTTP routes), see [Registering a Workflow Runner](/runs/registering-a-workflow-runner).
::
