`AgenticWorkflowLoop` separates orchestration logic (budgets, deduplication, stage progression, checkpointing, cancellation) from domain I/O (vector queries, web searches, scraping, LLM judgments). You plug in only the adapters your workflow needs — two are required (`targetExecutor` and `evaluator`), and four are optional.

## The six adapters

::accordion
  :::accordion-item{label="1. LocalKnowledgeAdapter<TLocalItem> (optional)" icon="i-lucide-database"}
  Pages through already-indexed local evidence (such as your vector database via `fetchRelevantChunks()`) before spending external search or crawl budget. Omit it or set `skipLocal: true` for external-only workflows.

  - `fetchBatch(offset, limit, state, context)`: returns up to `limit` local items, or `[]` when exhausted.
  - `getId(item)`: returns a stable `string | number` ID used to populate `state.seenLocalIds` and prevent duplicates across batches.
  - `getScore?(item)`: optional numeric relevance score logged for diagnostics.
  - `formatEvidence(item)`: converts an item into an evidence string, or returns `null` to skip it.
  :::

  :::accordion-item{label="2. ExternalDiscoveryAdapter<TDiscoveryPayload, TTarget> (optional)" icon="i-lucide-compass"}
  Turns pending search intents produced by `evaluator` into executable targets. Omit it if your workflow only executes pre-supplied `seedTargets`.

  - `discover(intent, context)`: searches for one intent (invoked concurrently across all intents in a round) and returns a raw payload.
  - `extractPassiveEvidence?(intent, payload)`: optionally extracts immediate evidence snippets (for example, search engine abstracts) from `payload` before executing targets.
  - `extractCandidates(intent, payload)`: maps `payload` into `TTarget[]` candidates (capped by `budgets.maxTargetsPerIntent`).
  :::

  :::accordion-item{label="3. TargetExecutorAdapter<TTarget, TExternalArtifact> (required)" icon="i-lucide-play"}
  Performs the concrete work for each target (crawling a URL, querying an API, parsing a file) and writes results into `state`.

  - `getKey(target)`: stable deduplication key recorded in `state.attemptedTargets`.
  - `isBlocked?(target)`: optional guard returning `{ blocked: boolean; reason?: string }` to skip disallowed domains or rate-limited hosts without spending effort.
  - `maxConsecutiveEmptyTargets?`: optional hint property for your own executor logic.
  - `executeBatch(targets, state, context)`: processes non-attempted, non-blocked targets, appends accepted text via `state.appendEvidence(...)` (or `state.evidenceSet`), pushes raw outputs into `state.externalArtifacts`, and returns `true` only if at least one target added evidence.
  :::

  :::accordion-item{label="4. EvaluatorAdapter (required)" icon="i-lucide-check-circle"}
  Decides between rounds whether accumulated evidence already answers `query`, or proposes new search intents for the next round.

  - `evaluate(input, context)`: receives `{ query, phaseDescription, evidenceText, issuedOrExhaustedIntents }` and returns `{ isSufficient: boolean, nextIntents: string[] }`.
  - `transformIntent?(intent)`: optional rewrite hook before discovery (for example, scoping every query with `site:docs.vendor.com`).
  - `fingerprint?(intent)`: normalizes intents so rephrasings map to one deduplication key. Defaults to `fingerprintQuery()`.
  :::

  :::accordion-item{label="5. CriticAdapter<TLocalItem, TExternalArtifact> (optional)" icon="i-lucide-eye"}
  Performs an optional quality audit on the full `WorkflowState` before finishing.

  - `review(state, context)`: returns `{ approved: boolean, notes?: string, followUpIntents?: string[] }`.
  - If `approved` is `false` and `followUpIntents` are supplied (while external budget remains), the loop executes additional external rounds to close the gaps. `notes` is preserved on `WorkflowRunResult.criticNotes`.
  :::

  :::accordion-item{label="6. FinalAnswerAdapter<TLocalItem, TExternalArtifact, TReport> (optional)" icon="i-lucide-sparkles"}
  Synthesizes the accumulated `WorkflowRunResult` into a strongly typed domain report placed at `result.report`.

  - `synthesize(result, context)`: receives the complete run result (`context`, `localItems`, `externalArtifacts`, `criticNotes`, `isSufficient`, `stopReason`) and returns `Promise<TReport>`.
  :::
::

## `WorkflowExecutionContext`

Every adapter call receives a `WorkflowExecutionContext` with two members:

```ts [src/adapter-context.ts]
import type { WorkflowExecutionContext } from "@riavzon/ai";

async function processTarget(url: string, ctx: WorkflowExecutionContext) {
  ctx.signal?.throwIfAborted();
  const data = await fetchPage(url, { signal: ctx.signal });

  ctx.emit({
    label: `Fetched ${url}`,
    addedEvidence: Boolean(data),
    message: data ? undefined : "Empty body",
    custom: { url, bytes: data?.length ?? 0 },
  });
}
```

The loop automatically tags each `ctx.emit(...)` update with `workflow: config.name` and the current `stage` before forwarding it to `config.onProgress`.

## Termination guarantees (`WorkflowBudgets`)

Every field in `WorkflowBudgets` is a hard cap enforced by the loop. Together they guarantee every run terminates cleanly even when external searches fail or an LLM evaluator repeatedly proposes redundant queries.

::field-group
  :::field{name="maxLocalRounds" type="number" required}
  Maximum number of `localKnowledge.fetchBatch()` calls across the entire run. Set `0` to skip local retrieval.
  :::

  :::field{name="maxExternalRounds" type="number" required}
  Maximum number of external discovery + execution rounds. Set `0` to skip external discovery.
  :::

  :::field{name="localBatchSize" type="number" required}
  Page size (`limit`) requested on each `localKnowledge.fetchBatch(offset, limit)` call.
  :::

  :::field{name="maxIntentsPerRound" type="number" required}
  Maximum search intents taken from `evaluator.evaluate().nextIntents` in a single round.
  :::

  :::field{name="maxTargetsPerIntent" type="number" required}
  Maximum candidate targets kept from one intent's `extractCandidates()` result.
  :::

  :::field{name="maxEvaluatorItems" type="number" required}
  Maximum evidence blocks retained in `state.evidenceSet` (oldest blocks are dropped when exceeded so evaluator prompts stay bounded).
  :::

  :::field{name="maxConsecutiveInsufficientLocalBatches" type="number" required}
  Consecutive local batches producing no new evidence before the local stage stops early and transitions to external discovery.
  :::

  :::field{name="maxSkippedExternalRounds" type="number" required}
  Consecutive external rounds with zero unattempted/unblocked targets before ending with `stopReason: "no_new_sources"`.
  :::

  :::field{name="maxRepeatedIntentRounds" type="number" required}
  Consecutive rounds where the evaluator only proposes already-searched intent fingerprints before terminating.
  :::

  :::field{name="maxDiscoveryFailuresPerIntent" type="number" required}
  Failed `discover()` attempts allowed per intent fingerprint before marking that intent exhausted.
  :::
::

::tip
Because `WorkflowState.toCheckpoint()` intentionally omits `budgets`, you can tune `WorkflowBudgets` across deployments and resume an in-flight workflow under updated caps without invalidating saved checkpoints.
::
