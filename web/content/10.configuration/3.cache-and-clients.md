Once `configuration()` has run, your application can reuse the same OpenAI clients and cache layer (Redis or in-memory) that `@riavzon/ai` uses — avoiding duplicate client singletons and manual cache branching.

## Access OpenAI clients (`aiClients`)

`aiClients(type?: "default" | "embedding")` returns your configured `OpenAI` instance. Calling `aiClients("embedding")` returns `embeddingConfig.client` if you configured a dedicated embedding provider, or falls back to your main OpenAI client.

```ts [src/use-clients.ts]
import { aiClients } from "@riavzon/ai";

// Chat / completion client
const chatClient = aiClients();
// Equivalent to: aiClients("default")

// Embedding client (uses embeddingConfig.client, falling back to the main client)
const embedClient = aiClients("embedding");

const completion = await chatClient.chat.completions.create({
  model: "gpt-4o-mini",
  messages: [{ role: "user", content: "Summarize this release note." }],
});
```

::warning
Calling `aiClients()` before `await configuration(...)` completes throws `"Ai clients not ready. Call configuration() first."`.
::

## Unified cache helpers (`cacheGet`, `cacheSet`, `cacheGetMany`, `cacheSetMany`)

All four cache functions work identically whether `configuration({ redis })` uses `"memory"` or an `ioredis` client:

- **TTL units**: Always pass `ttlMs` in **milliseconds**. On Redis, values are rounded up to whole seconds (minimum 1 second).
- **Batch pipelining**: `cacheGetMany()` fetches multiple keys in one batch (returning `[]` immediately on empty input), and `cacheSetMany()` pipelines writes into a single Redis round trip.

```ts [src/cache-helpers.ts]
import { cacheGet, cacheGetMany, cacheSet, cacheSetMany } from "@riavzon/ai";

// Single key read/write (5-minute TTL)
await cacheSet("rate:user_42", JSON.stringify({ remaining: 19 }), 5 * 60_000);
const raw = await cacheGet<string>("rate:user_42");

// Batched write in one Redis pipeline round trip (1-hour TTL)
await cacheSetMany(
  [
    { key: "doc:1:summary", value: "Billing policy overview" },
    { key: "doc:2:summary", value: "Refund SLA terms" },
  ],
  60 * 60_000,
);

// Batched read preserving key order (`null` for misses)
const values = await cacheGetMany([
  "doc:1:summary",
  "doc:2:summary",
  "doc:999:summary",
]);
// ["Billing policy overview", "Refund SLA terms", null]
```

## Custom loggers (`consoleLogger` & `Logger`)

Pass any `pino`-compatible object satisfying `Logger` (`debug`, `info`, `warn`, `error`, `child`) to `configuration({ logger })`. For lightweight scripts or tests, use `consoleLogger(bindings?)` to get child-logger support with zero external dependencies:

```ts [src/custom-logger.ts]
import { consoleLogger } from "@riavzon/ai";

const baseLogger = consoleLogger({ service: "ai-worker" });
const requestLogger = baseLogger.child({ requestId: "req_9a2f" });

requestLogger.info({ userId: "user_42" }, "Starting ingestion job");
```
