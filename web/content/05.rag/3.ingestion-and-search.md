`@riavzon/ai` stores ingested documents in two normalized tables (`documents` and `document_chunks`) and handles dialect differences between PostgreSQL (`pgvector`) and SQLite (`sqlite-vec`) automatically through `toVec()` and `getDistance()`.

## Ingest files (`saveUploadedScrappedFile`)

`saveUploadedScrappedFile()` accepts either a standard `FormData` upload (from browser or API routes) or an array of `UploadSource` objects (`File` or `{ name, data }`). For each accepted file it:

1. Filters by extension (defaults to `[".md", ".txt"]`).
2. Computes a SHA-256 content hash and skips files whose exact content already exists in `documents` (per user scope).
3. Runs `prepareScrape()` to chunk and embed the document.
4. Inserts the parent `documents` row and batch-inserts `document_chunks` (default `batchSize: 100`).

::tabs
:::tabs-item{label="From Disk or Memory" icon="i-lucide-file-text"}

```ts [src/ingest-files.ts]
import { readFile } from "node:fs/promises";
import { saveUploadedScrappedFile } from "@riavzon/ai";

const results = await saveUploadedScrappedFile(
  [
    {
      name: "pricing-faq.md",
      data: await readFile("./docs/pricing-faq.md", "utf-8"),
    },
    {
      name: "refund-policy.txt",
      data: await readFile("./docs/refund-policy.txt"),
    },
  ],
  "user_42", // Optional tenant/user owner ID
  {
    batchSize: 100,
    extensions: [".md", ".txt"],
    prepare: {
      maxTokens: 1000,
      overlapTokens: 100,
      embeddingConcurrency: 10,
    },
  },
);

console.log(results);
// {
//   ingested: ["pricing-faq.md", "refund-policy.txt"],
//   skippedDuplicates: [],
//   errors: []
// }
```

:::

:::tabs-item{label="From FormData Upload" icon="i-lucide-upload"}

```ts [src/routes/upload.ts]
import { saveUploadedScrappedFile } from "@riavzon/ai";

export async function POST(req: Request): Promise<Response> {
  const formData = await req.formData();
  const userId = req.headers.get("x-user-id") ?? undefined;

  const results = await saveUploadedScrappedFile(formData, userId);
  return Response.json(results);
}
```

## Search stored chunks

Use `searchDbDocs()` when you have a plain text query string, or `fetchRelevantChunks()` when you already have an embedding vector.

### High-level text search (`searchDbDocs`)

`searchDbDocs(conf, userId?)` embeds `conf.query` with `generateEmbedding()` and calls `fetchRelevantChunks()`. Validate untrusted query inputs with the exported `searchParams` Zod schema (`query` max 500 chars, `limit`, `offset` default `0`, `similarity` default `0.9`).

```ts [src/search-docs.ts]
import { searchDbDocs, searchParams } from "@riavzon/ai";

const parsed = searchParams.parse({
  query: "How do I configure Redis?",
  limit: 8,
  offset: 0,
  similarity: 0.55,
});

const result = await searchDbDocs(parsed, "user_42");

if (!Array.isArray(result)) {
  // { ok: false, date: "...", reason: "No available chunks found" }
  console.log("No matches:", result.reason);
} else {
  for (const chunk of result) {
    console.log(
      `[${chunk.similarity.toFixed(2)}] Doc #${chunk.documentId} (${chunk.title}):`,
      chunk.chunkText.slice(0, 120),
    );
  }
}
```

### Low-level vector search (`fetchRelevantChunks`)

`fetchRelevantChunks(queryVector, limit = 10, offset = 0, similarityThreshold = 0.1, userId?)` validates that `queryVector` has length `embeddingConfig.dimensions`, contains only finite values, and is non-zero, and validates that `limit` is an integer between `1` and `100`.

```ts [src/vector-query.ts]
import { fetchRelevantChunks, generateEmbedding } from "@riavzon/ai";

const vector = await generateEmbedding("PostgreSQL pgvector setup");

const chunks = await fetchRelevantChunks(
  vector,
  10, // limit (1..100)
  0, // offset
  0.4, // minimum cosine similarity (0..1)
  "user_42", // optional user_id filter
);
```

### `RelevantChunk` shape

| Property      | Type             | Description                                                                             |
| ------------- | ---------------- | --------------------------------------------------------------------------------------- |
| `id`          | `number`         | Row ID in `document_chunks`.                                                            |
| `documentId`  | `number \| null` | Foreign key to `documents.id` (pass to `readToolDocument()` to read the full document). |
| `chunkIndex`  | `number`         | Zero-based position of this chunk inside its document.                                  |
| `chunkText`   | `string`         | Chunk text body.                                                                        |
| `title`       | `string \| null` | Parent document title from `documents.title`.                                           |
| `retrievedAt` | `Date \| string` | Timestamp when the parent document was stored.                                          |
| `similarity`  | `number`         | Cosine similarity (`1 - cosine_distance`), ordered highest first.                       |

## Read full documents (`readToolDocument`)

When a chunk matches but you need the entire parent file (or a contiguous slice of up to 10 chunks), call `readToolDocument(userId, args)` directly — the same query powering the built-in `get_document` tool:

```ts [src/read-doc.ts]
import { readToolDocument } from "@riavzon/ai";

// Read the whole document (truncated to DOCUMENT_MAX_TOKENS, default 3000)
const whole = await readToolDocument("user_42", { documentId: 12 });

// Or read a specific inclusive chunk range (max 10 chunks per call)
const slice = await readToolDocument("user_42", {
  documentId: 12,
  chunkStart: 0,
  chunkEnd: 4,
});
```
