`@riavzon/ai` runs identically against a single SQLite file on your laptop and a multi-replica Kubernetes cluster backed by PostgreSQL (`pgvector`) and Redis. Because the database adapter, vector distance helper, and cache layer abstract backend differences behind `configuration()`, your agent and RAG code does not change as you scale.

## Topology comparison

Pick the deployment tier that matches your concurrency and durability requirements.

| Capability | Local / Single-Node (SQLite + Memory) | Production Single-Node (Postgres + Memory) | Multi-Replica Production (Postgres + Redis) |
| --- | --- | --- | --- |
| **Database** | SQLite file (`better-sqlite3` + `sqlite-vec`) | PostgreSQL (`pg` + `pgvector`) | PostgreSQL (`pg` + `pgvector`) |
| **Vector index** | `vec_distance_cosine()` scan over float32 blobs | HNSW `vector_cosine_ops` index | HNSW `vector_cosine_ops` index |
| **Tool & extractor cache** | Process-local `MiniCache` | Process-local `MiniCache` | Shared `ioredis` cache |
| **Semantic chat cache** | SQLite `messages.embedding` | Postgres HNSW index | Postgres HNSW index |
| **Generated files (`pdf_creator`, `create_styled_spreadsheet`)** | Disabled (`TOOL_DISABLED` without Redis) | Disabled (`TOOL_DISABLED` without Redis) | Enabled (cached in Redis under `file:<id>`) |
| **Durable run leases & crash recovery** | Supported (`runs` table) | Supported (`runs` table) | Supported across replicas (`runs` table) |
| **Cross-replica SSE reattach (`streamFromStore`)** | Local process only (`streamFromRun`) | Local process only (`streamFromRun`) | Full cross-replica replay via Redis Streams |

::warning
The built-in `pdf_creator` and `create_styled_spreadsheet` tools require a Redis backend (`redis: new Redis(...)`). When `redis` is left at its default `"memory"`, both tools return a `TOOL_DISABLED` tool error so generated download links never break across replicas or restarts.
::

## Single-node setup (SQLite + Memory)

For local development, CLI tools, desktop apps, or single-container services, pass a SQLite file path to `db` and omit `redis` (which defaults to `"memory"`).

```ts [src/infra/local.ts]
import OpenAI from "openai";
import { configuration } from "@riavzon/ai";

await configuration({
  db: "./data/assistant.db",
  openAiConfig: new OpenAI({ apiKey: process.env.OPENAI_API_KEY }),
  embeddingConfig: {
    dimensions: 1536,
    matchingModel: "text-embedding-3-small",
    retrievalModel: "text-embedding-3-small",
  },
});
```

During `configuration()`, `@riavzon/ai` automatically performs the following SQLite setup:

1. Loads `better-sqlite3` and the `sqlite-vec` native extension.
2. Enables `PRAGMA journal_mode = WAL`, `PRAGMA synchronous = NORMAL`, and `PRAGMA foreign_keys = ON`.
3. Runs Kysely migrations tracked in the `@riavzon/ai_migrations` table, creating `documents`, `document_chunks`, `conversations`, `messages`, and `runs`.

## Multi-replica production setup (PostgreSQL + Redis)

For horizontally scaled API servers and worker pools, pass a `pg.Pool` instance to `db` and an `ioredis` client to `redis`.

```ts [src/infra/production.ts]
import OpenAI from "openai";
import { Pool } from "pg";
import Redis from "ioredis";
import pino from "pino";
import { configuration, startRuns } from "@riavzon/ai";

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 20,
});

const redis = new Redis(process.env.REDIS_URL!);

await configuration({
  db: pool,
  redis,
  openAiConfig: new OpenAI({ apiKey: process.env.OPENAI_API_KEY }),
  embeddingConfig: {
    dimensions: 1536,
    matchingModel: "text-embedding-3-small",
    retrievalModel: "text-embedding-3-small",
  },
  logger: pino({ level: "info" }),
});

const stopRuns = startRuns();

process.on("SIGTERM", async () => {
  stopRuns();
  await redis.quit();
  await pool.end();
});
```

### PostgreSQL requirements

Ensure the `pgvector` extension is installed on your PostgreSQL server (for example `pgvector/pgvector:pg16` in Docker or a managed Postgres provider with `vector` enabled). The initial migration executes:

```sql [Automatic PostgreSQL setup]
CREATE EXTENSION IF NOT EXISTS vector;

CREATE INDEX IF NOT EXISTS "embeddingIndexChunk"
  ON document_chunks USING hnsw (embedding vector_cosine_ops);

CREATE INDEX IF NOT EXISTS "messageEmbeddingIndex"
  ON messages USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);
```

::caution
The `embeddingConfig.dimensions` value is baked into the PostgreSQL `vector(N)` columns during the first migration (`001_init`). Choose your embedding model and dimension count before running migrations in production. If you change dimensions later, migrate the `document_chunks.embedding` and `messages.embedding` columns manually and re-embed existing rows.
::

### How Redis is used

When you supply an `ioredis` client, `@riavzon/ai` uses it for four distinct workloads:

- **Tool result caching (`toolcache:*`)**: `withToolCache()` and `ToolSpec.cache` store JSON-serialized successful tool responses with a configurable TTL.
- **Generated file downloads (`file:<id>`)**: `pdf_creator` and `create_styled_spreadsheet` store base64 file payloads for `readGeneratedFile()`.
- **Extractor page cache**: The built-in `extractor` tool caches extracted and summarized web pages.
- **Cross-replica run streams (`run:events:<runId>`)**: The run system appends SSE frames via `XADD` with `MAXLEN ~` trimming and tails them via `XREAD BLOCK` on a duplicated blocking Redis connection.

::tip
Because `tailRun()` and `waitForNext()` duplicate your `ioredis` connection for blocking `XREAD` calls, make sure your Redis `maxclients` limit accounts for active SSE reattach readers on top of standard command connections.
::

## OpenAI-compatible providers

`openAiConfig` and `embeddingConfig.client` accept any instance compatible with the official `openai` SDK (`client.chat.completions.create` and `client.embeddings.create`). You can point `baseURL` at OpenRouter, Azure OpenAI, vLLM, Ollama, LiteLLM, or a separate embedding service without changing library code.

```ts [src/infra/custom-provider.ts]
import OpenAI from "openai";
import { configuration } from "@riavzon/ai";

await configuration({
  db: "./data/app.db",
  openAiConfig: new OpenAI({
    apiKey: process.env.OPENROUTER_API_KEY,
    baseURL: "https://openrouter.ai/api/v1",
  }),
  embeddingConfig: {
    client: new OpenAI({
      apiKey: process.env.OPENAI_API_KEY,
    }),
    dimensions: 1536,
    matchingModel: "text-embedding-3-small",
    retrievalModel: "text-embedding-3-small",
  },
});
```
