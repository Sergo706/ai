Writing crash-safe workflows by hand requires coordinating row creation, conditional lease claims, background heartbeat timers, abort-signal merging, transient-versus-permanent failure classification, and `finally` cleanup. `runWorkflow()` encapsulates that entire lifecycle in one function, while the checkpoint helpers let your workflow version and evolve its serialized state cleanly across deployments.

## Run a durable workflow (`runWorkflow`)

`runWorkflow(options, execute, log)` performs the complete lifecycle around your async `execute(ctx)` function:

1. Creates a new `runs` row and claims it (or atomically re-claims an existing row when `options.resumeRunId` is set).
2. Calls `options.onRunStarted?.(runId)`.
3. Starts a lease heartbeat (`startLeaseHeartbeat()`) and merges its abort controller with `options.signal` into `ctx.leaseSignal`.
4. Invokes `execute(ctx)` with `{ runId, leaseSignal, saveCheckpoint, loadCheckpoint, emitProgress }`.
5. On success, calls `finishRun()` with the final `partial` payload (`report`, plus optional `isSufficient`, `missingIntents`, and `meta`) and returns `WorkflowPayload<TData, TMeta>`.
6. On error:
   - If cancelled (`runWasAborted()`), releases the run with status `"aborted"`.
   - If transient (`isTransientError()`) **and** a checkpoint exists, marks the run `"interrupted"` so the recovery sweeper resumes it automatically.
   - Otherwise marks the run `"failed"` with the error message.

```ts [src/workflows/auditWorkflow.ts]
import {
  checkpoint,
  getConfiguration,
  parseCheckpoint,
  runWorkflow,
  type WorkflowRunOptions,
} from "@riavzon/ai";

interface AuditState {
  checkedUrls: string[];
  findings: string[];
}

const AUDIT_CHECKPOINT_SPEC = {
  version: 1,
  phases: ["crawl", "analyze", "report"] as const,
};

export async function runSiteAudit(
  options: Omit<WorkflowRunOptions, "kind" | "name">,
  targetUrls: string[],
) {
  const log = getConfiguration().logger;

  return runWorkflow(
    {
      ...options,
      kind: "workflow",
      name: "site-audit",
      input: { targetUrls },
    },
    async (ctx) => {
      // Restore saved progress if resuming an interrupted or retried run
      const raw = await ctx.loadCheckpoint();
      const saved = parseCheckpoint<
        AuditState,
        (typeof AUDIT_CHECKPOINT_SPEC.phases)[number]
      >(raw, AUDIT_CHECKPOINT_SPEC);

      const state: AuditState = saved?.state ?? {
        checkedUrls: [],
        findings: [],
      };

      const remaining = targetUrls.filter(
        (u) => !state.checkedUrls.includes(u),
      );

      for (const url of remaining) {
        ctx.leaseSignal.throwIfAborted();
        const finding = await inspectUrl(url, ctx.leaseSignal);
        state.checkedUrls.push(url);
        if (finding) state.findings.push(finding);

        ctx.emitProgress({
          label: `Audited ${url}`,
          addedEvidence: Boolean(finding),
        });

        // Fire-and-forget durable checkpoint saved to runs.checkpoint
        ctx.saveCheckpoint(
          checkpoint({
            phase: "crawl",
            state,
            roundsDone: state.checkedUrls.length,
          }),
        );
      }

      return {
        data: { findings: state.findings },
        stopReason: "sufficient",
        source: "external",
        isSufficient: true,
        missingIntents: [],
        meta: { checkedUrls: state.checkedUrls },
      };
    },
    log,
  );
}
```

## Versioned checkpoint helpers

Workflow state schemas evolve over time. Wrapping state in a versioned `Checkpoint<TState, TPhase>` envelope guarantees that old rows written by a previous deploy never crash a new release:

::field-group
:::field{name="checkpoint({ phase, state, version?, roundsDone? })" type="Checkpoint<TState, TPhase>"}
Wraps workflow progress in a standardized envelope. `version` defaults to `DEFAULT_CHECKPOINT_VERSION` (`1`). Bump `version` whenever `state` changes shape incompatibly.
:::

:::field{name="parseCheckpoint(value, { version, phases })" type="Checkpoint<TState, TPhase> | null"}
Validates that an unknown value loaded from `runs.checkpoint` matches the expected `version`, has a `phase` present in `phases`, and holds a non-null object `state`. Returns `null` on mismatch so the workflow cleanly restarts from the beginning instead of crashing.
:::

:::field{name="restore(target, from, restoreState)" type="TState"}
Copies saved progress from `from.state` into a freshly constructed live state object `target` (useful for reviving `Map` and `Set` fields while keeping current deployment budgets/config fresh).
:::

:::field{name="saveCheckpoint({ runId, snapshot }) / loadCheckpoint(runId)" type="DB model helpers"}
Persist or fetch `runs.checkpoint` directly outside `runWorkflow()`.
:::
::

### Copying progress onto fresh config with `restore()`

```ts [src/restore-example.ts]
import { restore, type Checkpoint } from "@riavzon/ai";

interface CrawlProgress {
  maxConcurrency: number; // Always taken from current deploy
  visited: string[]; // Restored from checkpoint
  findings: string[]; // Restored from checkpoint
}

function hydrate(ckpt: Checkpoint<CrawlProgress, "crawl">): CrawlProgress {
  const fresh: CrawlProgress = {
    maxConcurrency: 8,
    visited: [],
    findings: [],
  };

  return restore(fresh, ckpt, (target, saved) => {
    target.visited = [...saved.visited];
    target.findings = [...saved.findings];
  });
}
```

## Error classification (`isTransientError`, `isAbortError`, `runWasAborted`)

`@riavzon/ai` exports the classifiers used by `runWorkflow()` so you can reuse the same retry and abort checks in custom workers:

- `isAbortError(error)`: returns `true` for `AbortError`, `RequestAbortedError`, `WorkflowAbortedError`, OpenAI `APIUserAbortError`, and Node abort error codes.
- `runWasAborted({ error, signal, leaseAborted })`: returns `true` if the signal aborted, the lease was marked aborted, or `isAbortError(error)` matches.
- `isTransientError(error)`: walks nested `error.cause` chains safely (with cycle detection) and treats retryable network failures (such as `ECONNRESET`, `ETIMEDOUT`, `EAI_AGAIN`, and undici timeout/socket errors), retryable HTTP statuses (`408`, `425`, `429`, `500`, `502`, `503`, `504`, `522`, `524`), and timeout messages as transient — while returning `false` for deterministic `4xx` errors, validation failures, and aborts. Inside `runWorkflow()`, a transient error marks the run `"interrupted"` only when a checkpoint exists (so recovery adopts it); without a checkpoint, the run is marked `"failed"`.

### How `saveCheckpoint()` protects successors

`saveCheckpoint({ runId, snapshot })` writes only while the current replica still owns the run lease, and logs database errors instead of throwing:

- **Fenced zombie protection**: If a paused process wakes up after another replica takes over the lease, its stale checkpoint write is skipped with a warning rather than overwriting newer progress.
- **Non-fatal writes**: Because a missed checkpoint only costs re-running the latest round on crash, a brief database hiccup never fails a healthy workflow.

### How `runWorkflow()` handles lost leases

When the heartbeat reports `"aborted"`, `"terminated"`, `"lost"`, or `"gone"`, `runWorkflow()` aborts `ctx.leaseSignal`, releases its lease on exit, and skips writing a terminal status so a fenced worker never overwrites a user cancellation or a newer replica's update.
