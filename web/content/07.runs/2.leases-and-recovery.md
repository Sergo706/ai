In a horizontally scaled deployment, multiple server replicas share the same SQL database and Redis cluster. `@riavzon/ai` uses optimistic conditional SQL leases to ensure only one replica executes a given run, detect dead workers automatically, and propagate cancel signals across instances.

## Process identity & lease primitives

Every process automatically generates a unique `INSTANCE_ID` (`<hostname>:<pid>:<random>`). Lease operations in `@riavzon/ai` operate conditionally against `runs.owner` and `runs.claimed_at`:

| Function                                           | Purpose                                                                                                                                                                                                                                   |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `claimRun(runId)`                                  | Atomically claims a run for `INSTANCE_ID` if unowned, expired, or interrupted. Keeps `attempts` at `0` on a brand-new unclaimed run and increments by `1` on takeover or resume. Returns `true` only to the winning replica.              |
| `heartbeatRun(runId)`                              | Refreshes the lease timestamp (`claimed_at`) and returns `LeaseState` (`"alive" \| "aborted" \| "terminated" \| "lost" \| "gone"`).                                                                                                       |
| `startLeaseHeartbeat(runId, onLost, log)`          | Runs a periodic heartbeat (capped at half the lease TTL) and invokes `onLost(state)` if the lease returns anything other than `"alive"`.                                                                                                  |
| `requestAbort(runId)`                              | Marks the run `"aborted"` while leaving `owner` intact during unwind, so the owning replica receives `"aborted"` on its next heartbeat and cancels its `AbortController`.                                                                 |
| `finishRun({ runId, stopReason, partial })`        | Atomically marks a running row owned by this replica as `"finished"` and saves `partial`.                                                                                                                                                 |
| `releaseRun(runId)`                                | Clears lease ownership for this replica so another replica can take over; call it on both success and failure paths.                                                                                                                      |
| `markStaleRunsInterrupted()`                       | Marks expired uncheckpointed `running` rows as `"interrupted"` (called automatically by `startRuns()`).                                                                                                                                   |
| `findResumableRuns(limit = 10, kind = "workflow")` | Returns up to `limit` runs of `kind` that have an expired lease or an `"interrupted"` status with a saved checkpoint (attempt caps are enforced by `startRunRecovery()`).                                                                 |

### Cancelling a run from any HTTP replica

Because a stop request (`POST /api/runs/:id/stop`) can land on a different replica than the one executing the run, always cancel both locally (for instant response if on the same node) and in SQL (for cross-replica propagation):

```ts [src/routes/stop-run.ts]
import { getRun, requestAbort } from "@riavzon/ai";

export async function POST(
  _req: Request,
  { params }: { params: { runId: string } },
): Promise<Response> {
  // Instant abort if this process owns the run
  const local = getRun(params.runId);
  local?.controller.abort();

  // Persistent flag so another replica stops on its next heartbeat tick
  const flagged = await requestAbort(params.runId);

  return Response.json({ ok: Boolean(local || flagged) });
}
```

## Register resumers (`registerRunResumer`)

When a process restarts or crashes mid-run, the recovery sweeper loads candidate rows and matches `(row.kind, row.input.name)` against the resumer registry using `findRunResumer(kind, name)` — exact `(kind, name)` matches take precedence over an unnamed `kind`-only fallback.

- **Workflows**: Register a resumer explicitly for every durable workflow before calling `startRuns()`.
- **Chat turns (`kind: "chat"`)**: Deliberately never auto-registered or auto-resumed. Chat turns are short, mostly cached, and blindly replaying a tool round risks duplicating assistant messages or regenerating files — retrying from the UI is the intended UX.

```ts [src/resumers/researchResumer.ts]
import {
  attachDetachedWorkflow,
  fromJson,
  getConfiguration,
  lastStreamId,
  registerRunResumer,
  runProgressFrames,
  runWorkflow,
} from "@riavzon/ai";

registerRunResumer({
  kind: "workflow",
  name: "research",
  adopt: async (row) => {
    const log = getConfiguration().logger;
    const input = fromJson<{ query?: string }>(row.input);
    const query = input?.query ?? row.query;

    // Seed stream IDs after whatever the dead replica already wrote to Redis
    const seedAfterId = await lastStreamId(row.id);
    const detached = attachDetachedWorkflow({
      runId: row.id,
      kind: "workflow",
      conversationId: row.conversation_id ?? undefined,
      seedAfterId,
      log,
    });

    const progress = runProgressFrames(
      detached.tee(() => {}),
      {
        query,
        workflow: "research",
      },
    );

    try {
      const payload = await runWorkflow(
        {
          resumeRunId: row.id,
          kind: "workflow",
          name: "research",
          query,
          userId: row.user_id ?? undefined,
          conversationId: row.conversation_id ?? undefined,
          signal: detached.run.controller.signal,
          onProgress: progress.onProgress,
        },
        async (ctx) => executeResearchFromCheckpoint(ctx, query),
        log,
      );

      detached.finish({ type: "research_result", payload });
    } catch (err) {
      // Losing a claim race to another replica is expected; avoid emitting error frames
      if (String(err).includes("already owned")) return;
      detached.fail();
    }
  },
});
```

::note
Keep `name` stable across deployments. `runs.input.name` is stored when a run starts and matched verbatim against registered resumers when recovering older rows.
::

### Recovery safety guarantees

- **Rolling-deploy grace window (`unclaimedGraceMs`)**: If a replica finds an abandoned run whose `(kind, input.name)` has no matching resumer on that node (for example, an older pod seeing a run from a newer release), recovery leaves it untouched for `RUNS_UNCLAIMED_GRACE_MS` (default `600000` ms / 10 minutes) before marking it `"failed"`.
- **Exact attempt accounting**: A brand-new unclaimed run stays at `attempts: 0` on its first claim. A crash takeover increments `attempts` by `1`. Manual retries (`reopenRunForRetry()`) increment `attempts` by `1` and clear the previous owner so the subsequent claim inside `adopt()` does not double-count.

::tip
See [Registering a Workflow Runner](/runs/registering-a-workflow-runner) for a complete end-to-end example connecting boot plugins, defensive `runs.input` deserializers, shared `runWorkflow()` runners, and HTTP routes.
::

### Inspecting recovery settings

Use `listRunResumers()`, `findRunResumer(kind, name)`, `getMaxResumeAttempts()`, `getRunRecoverySettings()`, `getLeaseTtlMs()`, and `getHeartbeatIntervalMs()` to expose health or diagnostics endpoints.

```ts [src/routes/run-health.ts]
import {
  getHeartbeatIntervalMs,
  getLeaseTtlMs,
  getRunRecoverySettings,
  INSTANCE_ID,
  listRunResumers,
} from "@riavzon/ai";

export function GET(): Response {
  return Response.json({
    instance: INSTANCE_ID,
    leaseTtlMs: getLeaseTtlMs(),
    heartbeatIntervalMs: getHeartbeatIntervalMs(),
    recovery: getRunRecoverySettings(),
    resumers: listRunResumers().map((r) => ({
      kind: r.kind,
      name: r.name ?? null,
    })),
  });
}
```

## Manual user retries (`retryRun`)

The automatic sweeper intentionally never touches `aborted` or `failed` runs. When a user clicks **Retry** in your UI, call `retryRun(runId)`. It reopens the row via `reopenRunForRetry()` (preserving any saved checkpoint!), checks `maxResumeAttempts`, looks up the matching resumer, and invokes `resumer.adopt(reopened)` asynchronously.

```ts [src/routes/retry-run.ts]
import { retryRun } from "@riavzon/ai";

export async function POST(
  _req: Request,
  { params }: { params: { runId: string } },
): Promise<Response> {
  const outcome = await retryRun(params.runId);

  if (!outcome.ok) {
    const status = outcome.reason === "not_found" ? 404 : 409;
    return Response.json(outcome, { status });
  }

  // { ok: true, runId, kind, name, resumed: boolean, attempts: number }
  return Response.json(outcome);
}
```

### `RetryFailureReason` values

- `"not_found"`: No row exists for `runId`.
- `"no_runner"`: No registered resumer matches `(row.kind, row.input.name)`.
- `"already_running"`: The run is currently active or changed state concurrently before reopening.
- `"attempts_exhausted"`: `row.attempts` has reached `maxResumeAttempts` (ask the user to start a fresh run).

## Load-bearing lease and recovery guarantees

### Dual meaning of `interrupted`

An `interrupted` run behaves differently depending on whether it has a saved checkpoint:

- **`interrupted` without a checkpoint**: Written at boot by `markStaleRunsInterrupted()` for expired runs that have no checkpoint (such as chat turns or workflows that crashed early). The recovery sweep never adopts these rows.
- **`interrupted` with a checkpoint**: Written by `runWorkflow()` when a transient error (`isTransientError()`) hits after at least one checkpoint was saved. The recovery sweep adopts the run automatically once the lease TTL has elapsed and attempts remain below `maxResumeAttempts`.

### Atomic ownership and fencing guarantees

- **Atomic single-query claim**: `claimRun()` claims a run conditionally in one atomic database update instead of reading and then writing. It accepts only `running`, `interrupted`, or `failed` rows that are unowned or past the lease TTL, and always refuses `finished` and `aborted` rows.
- **5-way `LeaseState`**: `heartbeatRun()` returns `"alive"`, `"aborted"`, `"terminated"`, `"lost"`, or `"gone"` so a worker can distinguish a user stop (`"aborted"`) from another replica closing or taking over the run and exit cleanly without overwriting the row.
- **Clamped heartbeat interval**: `getHeartbeatIntervalMs()` is capped at half of `leaseTtlMs`, so a misconfigured interval can never cause a healthy worker to expire its own lease.
- **Safe abort unwinding**: `requestAbort()` sets `status` to `"aborted"` while leaving lease ownership intact until the worker unwinds, preventing another replica from adopting the run prematurely.
- **Fenced completion**: `finishRun()` succeeds only if the run is still `"running"` and owned by the current replica, so a slow or fenced worker can never overwrite a concurrent stop or takeover.
- **Checkpoint-safe boot reconciliation**: `markStaleRunsInterrupted()` only marks rows whose lease has expired **and** that have no checkpoint — so sibling replicas keep running untouched, and checkpointed workflows stay resumable across restarts.
- **Unclaimed manual retries**: `reopenRunForRetry()` sets `status` back to `"running"`, increments `attempts`, and clears the previous owner so `adopt()` follows the same claim flow as automatic recovery without double-counting attempts.

### Complete state × action decision table

| Row state                                           | Automatic recovery sweep                                                             | Manual `retryRun()`                                                              | Reattach stream (`streamFromStore`)                                       |
| --------------------------------------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `running`, fresh lease                              | Ignored (healthy owner)                                                              | Refused (`already_running`)                                                      | Replays history and tails live events                                     |
| `running`, expired lease (or unclaimed past TTL)    | Adopted by matching resumer if attempts remain; otherwise marked `failed`            | Refused (`already_running`)                                                      | Tails until resumed or closed; stops when `isRunAlive()` returns `false`  |
| `interrupted`, with checkpoint                      | Adopted automatically after `leaseTtlMs` if attempts remain                          | Reopened and adopted if attempts remain                                          | Replays stored events; closes cleanly once `isRunAlive()` returns `false` |
| `interrupted`, without checkpoint                   | Ignored (nothing to resume from)                                                     | Reopened from scratch if a resumer exists and attempts remain                    | Replays stored events then closes                                         |
| `failed`                                            | Ignored                                                                              | Reopened and adopted (preserving any checkpoint) if attempts remain              | Replays stored events including the final `error` frame then closes       |
| `aborted`                                           | Ignored (never auto-resumed)                                                         | Reopened and adopted (preserving any checkpoint) if attempts remain              | Replays stored events then closes                                         |
| `finished`                                          | Ignored                                                                              | Refused (`already_running`)                                                      | Replays stored events including the `done` frame then closes              |
