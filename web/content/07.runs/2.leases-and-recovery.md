In a horizontally scaled deployment, multiple server replicas share the same SQL database and Redis cluster. `@riavzon/ai` uses optimistic conditional SQL leases to ensure only one replica executes a given run, detect dead workers automatically, and propagate cancel signals across instances.

## Process identity & lease primitives

Every process automatically generates a unique `INSTANCE_ID` (`<hostname>:<pid>:<random>`). Lease operations in `@riavzon/ai` operate conditionally against `runs.owner` and `runs.claimed_at`:

| Function | Purpose |
| --- | --- |
| `claimRun(runId)` | Atomically claims a run for `INSTANCE_ID` if unowned, stale, or interrupted. Adds `0` to `attempts` on an initial untouched claim (`status = "running"` and `owner IS NULL`) and `+1` on takeover/resume. Returns `true` only to the winning replica. |
| `heartbeatRun(runId)` | Refreshes `claimed_at` and returns `LeaseState` (`"alive" \| "aborted" \| "terminated" \| "lost" \| "gone"`). |
| `startLeaseHeartbeat(runId, onLost, log)` | Starts an interval (clamped to ≤ `leaseTtlMs / 2`) that calls `heartbeatRun()` and invokes `onLost(state)` if the lease returns any state other than `"alive"`. |
| `requestAbort(runId)` | Marks `runs.status = "aborted"` in SQL (while keeping `owner` intact during unwind) so whichever replica holds the lease receives `"aborted"` on its next heartbeat tick and cancels its `AbortController`. |
| `finishRun({ runId, stopReason, partial })` | Atomically transitions the run to `finished` (fenced by `owner = INSTANCE_ID` and `status = "running"`) and stores `partial`. |
| `releaseRun(runId)` | Clears `owner` and `claimed_at` (fenced by `owner = INSTANCE_ID`) so another replica can take over; call on both success and failure paths. |
| `markStaleRunsInterrupted()` | Marks expired `running` rows (`claimed_at < now - leaseTtlMs`) as `interrupted` (invoked automatically by `startRuns()`). |
| `findResumableRuns(limit = 10, kind = "workflow")` | Returns up to `limit` runs of `kind` that are `running` with a stale claim or `interrupted` with a non-null checkpoint ready for recovery (attempt limits are enforced by `startRunRecovery()`). |

### Cancelling a run from any HTTP replica

Because a stop request (`POST /api/runs/:id/stop`) can land on a different replica than the one executing the run, always cancel both locally (for instant response if on the same node) and in SQL (for cross-replica propagation):

```ts [src/routes/stop-run.ts]
import { getRun, requestAbort } from "@riavzon/ai";

export async function POST(
  _req: Request,
  { params }: { params: { runId: string } },
): Promise<Response> {
  // Instant abort if this process owns the run
  const local = getRun(params.runId);
  local?.controller.abort();

  // Persistent flag so another replica stops on its next heartbeat tick
  const flagged = await requestAbort(params.runId);

  return Response.json({ ok: Boolean(local || flagged) });
}
```

## Registering resumers (`registerRunResumer`)

When a process restarts or crashes mid-run, the recovery sweeper loads candidate rows and matches `(row.kind, row.input.name)` against the resumer registry using `findRunResumer(kind, name)` — exact `(kind, name)` matches take precedence over an unnamed `kind`-only fallback.

- **Workflows**: Register a resumer explicitly for every durable workflow before calling `startRuns()`.
- **Chat turns (`kind: "chat"`)**: Deliberately never auto-registered or auto-resumed. Chat turns are short, mostly cached, and blindly replaying a tool round risks duplicating assistant messages or regenerating files — retrying from the UI is the intended UX.

```ts [src/resumers/researchResumer.ts]
import {
  attachDetachedWorkflow,
  fromJson,
  getConfiguration,
  lastStreamId,
  registerRunResumer,
  runProgressFrames,
  runWorkflow,
} from "@riavzon/ai";

registerRunResumer({
  kind: "workflow",
  name: "research",
  adopt: async (row) => {
    const log = getConfiguration().logger;
    const input = fromJson<{ query?: string }>(row.input);
    const query = input?.query ?? row.query;

    // Seed stream IDs after whatever the dead replica already wrote to Redis
    const seedAfterId = await lastStreamId(row.id);
    const detached = attachDetachedWorkflow({
      runId: row.id,
      kind: "workflow",
      conversationId: row.conversation_id ?? undefined,
      seedAfterId,
      log,
    });

    const progress = runProgressFrames(detached.tee(() => {}), {
      query,
      workflow: "research",
    });

    try {
      const payload = await runWorkflow(
        {
          resumeRunId: row.id,
          kind: "workflow",
          name: "research",
          query,
          userId: row.user_id ?? undefined,
          conversationId: row.conversation_id ?? undefined,
          signal: detached.run.controller.signal,
          onProgress: progress.onProgress,
        },
        async (ctx) => executeResearchFromCheckpoint(ctx, query),
        log,
      );

      detached.finish({ type: "research_result", payload });
    } catch (err) {
      // Losing a claim race to another replica is expected; avoid emitting error frames
      if (String(err).includes("already owned")) return;
      detached.fail();
    }
  },
});
```

::note
Keep `name` stable across deployments. `runs.input.name` is stored when a run starts and matched verbatim against registered resumers when recovering older rows.
::

### Recovery safety guarantees

- **Rolling-deploy grace window (`unclaimedGraceMs`)**: If a replica discovers an abandoned run whose `(kind, input.name)` has no matching resumer on that replica (common during rolling deployments when an older pod inspects a run created by a newer pod), recovery leaves the row untouched for `RUNS_UNCLAIMED_GRACE_MS` (default `600000` ms / 10 minutes) before marking it `failed`.
- **Exact attempt accounting (no double-counting)**: A brand-new run claimed by its creator (`status = "running"` and `owner IS NULL`) keeps `attempts = 0`. A crash takeover increments `attempts` by `1`. Manual retries (`reopenRunForRetry()`) increment `attempts` by `1` and reset `owner = null` so the subsequent `claimRun()` inside `adopt()` adds `0`.

::tip
See [Registering a Workflow Runner](/runs/registering-a-workflow-runner) for a complete end-to-end example connecting boot plugins, defensive `runs.input` deserializers, shared `runWorkflow()` runners, and HTTP routes.
::

### Inspecting recovery settings

Use `listRunResumers()`, `findRunResumer(kind, name)`, `getMaxResumeAttempts()`, `getRunRecoverySettings()`, `getLeaseTtlMs()`, and `getHeartbeatIntervalMs()` to expose health or diagnostics endpoints.

```ts [src/routes/run-health.ts]
import {
  getHeartbeatIntervalMs,
  getLeaseTtlMs,
  getRunRecoverySettings,
  INSTANCE_ID,
  listRunResumers,
} from "@riavzon/ai";

export function GET(): Response {
  return Response.json({
    instance: INSTANCE_ID,
    leaseTtlMs: getLeaseTtlMs(),
    heartbeatIntervalMs: getHeartbeatIntervalMs(),
    recovery: getRunRecoverySettings(),
    resumers: listRunResumers().map((r) => ({ kind: r.kind, name: r.name ?? null })),
  });
}
```

## Manual user retries (`retryRun`)

The automatic sweeper intentionally never touches `aborted` or `failed` runs. When a user clicks **Retry** in your UI, call `retryRun(runId)`. It reopens the row via `reopenRunForRetry()` (preserving any saved checkpoint!), checks `maxResumeAttempts`, looks up the matching resumer, and invokes `resumer.adopt(reopened)` asynchronously.

```ts [src/routes/retry-run.ts]
import { retryRun } from "@riavzon/ai";

export async function POST(
  _req: Request,
  { params }: { params: { runId: string } },
): Promise<Response> {
  const outcome = await retryRun(params.runId);

  if (!outcome.ok) {
    const status = outcome.reason === "not_found" ? 404 : 409;
    return Response.json(outcome, { status });
  }

  // { ok: true, runId, kind, name, resumed: boolean, attempts: number }
  return Response.json(outcome);
}
```

### `RetryFailureReason` values

- `"not_found"`: No row exists for `runId`.
- `"no_runner"`: No registered resumer matches `(row.kind, row.input.name)`.
- `"already_running"`: The run is currently active or changed state concurrently before reopening.
- `"attempts_exhausted"`: `row.attempts` has reached `maxResumeAttempts` (ask the user to start a fresh run).

## Load-bearing lease & recovery invariants

### Dual meaning of `interrupted`

An `interrupted` row has two distinct meanings depending on whether `checkpoint` is populated:

- **`interrupted` with `checkpoint IS NULL`**: Written at boot by `markStaleRunsInterrupted()` for uncheckpointed stale runs (such as chat turns or workflows that crashed before saving a checkpoint). The recovery sweep **never** adopts it.
- **`interrupted` with `checkpoint IS NOT NULL`**: Written by `runWorkflow()` when a **transient error** (`isTransientError()`) occurs after at least one checkpoint was saved. The recovery sweep **automatically adopts** it once `finished_at` is older than `leaseTtlMs` (and `attempts < maxResumeAttempts`).

### Atomic SQL & fencing guarantees

- **Single-query conditional `claimRun()`**: Uses one atomic `UPDATE ... WHERE status IN ('running', 'interrupted', 'failed') AND (claimed_at IS NULL OR claimed_at < staleBefore) RETURNING id` — never read-then-write. `finished` and `aborted` are closed doors that `claimRun()` always refuses.
- **5-way `LeaseState` distinguishes user stop from takeover**: `heartbeatRun()` returns `"alive" | "aborted" | "terminated" | "lost" | "gone"` so a fenced worker knows whether a user cancelled it (`"aborted"`) or another process closed/took over the row (`"terminated"` / `"lost"` / `"gone"`) and unwinds without overwriting the row.
- **Clamped intervals prevent silent misconfiguration**: `getHeartbeatIntervalMs()` is clamped to `<= floor(leaseTtlMs / 2)`, so a slow heartbeat can never let a healthy worker expire its own lease.
- **`requestAbort()` leaves `owner` intact**: Marking `status = "aborted"` keeps `owner` and `claimed_at` in place while the owning worker unwinds so another replica cannot adopt it prematurely and late `saveCheckpoint()` calls stay quiet.
- **Conditional `finishRun()`**: Guards `WHERE status = 'running' AND owner = INSTANCE_ID` so neither a late completion nor a fenced zombie can overwrite a concurrent `aborted` status or a successor's row.
- **Checkpoint-safe boot reconciliation**: `markStaleRunsInterrupted()` requires **both** `claimed_at < staleBefore` (multi-replica safety: never kill runs owned by healthy sibling replicas) **and** `checkpoint IS NULL` (never mark checkpointed resumable runs unresumable on restart).
- **Unclaimed manual retries**: `reopenRunForRetry()` sets `status = "running"`, increments `attempts`, and clears `owner = NULL, claimed_at = NULL` so `adopt()` runs the exact same `claimRun()` path as the recovery sweep without double-counting `attempts`.

### Complete state × action decision table

| Row state | Automatic recovery sweep | Manual `retryRun()` | Reattach stream (`streamFromStore`) |
| --- | --- | --- | --- |
| `running`, fresh `claimed_at` | Ignored (healthy owner) | Refused (`already_running`) | Replays history + live tails Redis Stream |
| `running`, stale `claimed_at` (or unclaimed past TTL) | Adopted by matching resumer if `attempts < maxResumeAttempts`; else marked `failed` | Refused (`already_running`) | Tails until resumed or closed; stops when `isRunAlive()` returns `false` |
| `interrupted`, `checkpoint IS NOT NULL` | Adopted automatically after `leaseTtlMs` if `attempts < maxResumeAttempts` | Reopened & adopted if `attempts < maxResumeAttempts` | Replays stored events; closes cleanly once `isRunAlive()` returns `false` |
| `interrupted`, `checkpoint IS NULL` | Ignored (nothing to resume from) | Reopened from scratch if resumer exists & `attempts < maxResumeAttempts` | Replays stored events then closes |
| `failed` | Ignored | Reopened & adopted (preserving checkpoint if any) if `attempts < maxResumeAttempts` | Replays stored events including final `error` frame then closes |
| `aborted` | Ignored (one-way door for sweep) | Reopened & adopted (preserving checkpoint if any) if `attempts < maxResumeAttempts` | Replays stored events then closes |
| `finished` | Ignored | Refused (`already_running` / non-reopenable) | Replays stored events including `done` frame then closes |
