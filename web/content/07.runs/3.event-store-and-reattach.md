Every frame emitted by a registered run is tagged once with a monotonic stream ID (`<epochMs>-<seq>`) and stored in both the owning process's memory (`RunRegistry`) and Redis Streams (`eventStore`). That shared ID space allows any HTTP client to disconnect and reconnect with a `Last-Event-ID` cursor — whether the reconnect lands on the same replica or another node behind a load balancer.

## Unified reattachment route

When a client reconnects to `GET /api/runs/:runId/stream` (passing `?since=` or the standard `Last-Event-ID` header), check `getRun(runId)` first for an in-process zero-hop stream and fall back to `streamFromStore()` for cross-replica replay via Redis Streams:

```ts [src/routes/reattach-run.ts]
import {
  FIRST_ID,
  getConfiguration,
  getRun,
  getRunById,
  setSseHeaders,
  streamFromRun,
  streamFromStore,
} from "@riavzon/ai";

export async function GET(
  req: Request,
  { params }: { params: { runId: string } },
): Promise<Response> {
  const url = new URL(req.url);
  const since =
    req.headers.get("last-event-id") ??
    url.searchParams.get("since") ??
    FIRST_ID;
  const log = getConfiguration().logger;

  // Fast path: run is executing (or recently settled) in this process
  const local = getRun(params.runId);
  if (local) {
    const stream = streamFromRun({
      run: local,
      since,
      conversationId: local.conversationId,
      runId: local.id,
      log,
    });
    return new Response(stream, { headers: setSseHeaders() });
  }

  // Verify the run exists before tailing Redis Streams
  const row = await getRunById(params.runId);
  if (!row) {
    return new Response("Run not found", { status: 404 });
  }

  // Cross-replica path: replay + live tail from Redis Streams
  const stream = streamFromStore({
    runId: row.id,
    since,
    conversationId: row.conversation_id ?? undefined,
    log,
    // Called only when the Redis Stream goes quiet; stops tailing if the run died
    isRunAlive: async () => {
      const latest = await getRunById(row.id);
      return latest?.status === "running" || latest?.status === "interrupted";
    },
  });

  return new Response(stream, { headers: setSseHeaders() });
}
```

::tip
When `isRunAlive()` returns `false`, `streamFromStore()` cleanly closes the SSE response instead of blocking forever — protecting clients if the replica running the workflow crashed without writing a terminal `done` or `error` frame.
::

## Stream a detached workflow (`workflowStreamWithRegistry`)

To start a custom workflow whose frames can immediately be replayed and reattached if the initial caller disconnects, wrap it in `workflowStreamWithRegistry()`:

```ts [src/routes/start-workflow.ts]
import {
  getConfiguration,
  runProgressFrames,
  setSseHeaders,
  workflowStreamWithRegistry,
} from "@riavzon/ai";

export async function POST(req: Request): Promise<Response> {
  const { query, conversationId } = await req.json();
  const runId = crypto.randomUUID();
  const log = getConfiguration().logger;

  const stream = workflowStreamWithRegistry({
    runId,
    kind: "workflow",
    conversationId,
    log,
    heartbeatMs: 10_000,
    execute: async ({ emit, signal }) => {
      const progress = runProgressFrames(emit, { query, workflow: "research" });
      progress.onRunStarted(runId);

      const report = await runMyResearch(query, {
        signal,
        onProgress: progress.onProgress,
      });

      return { type: "research_result", report };
    },
    onError: (err) => log.error({ err, runId }, "Workflow failed"),
  });

  return new Response(stream, { headers: setSseHeaders() });
}
```

For full manual control (such as inside a resumer's `adopt()` callback where there is no initial HTTP response), call `attachDetachedWorkflow({ runId, kind, conversationId, seedAfterId, log })` directly — it gives you `{ run, tee, finish, fail }`.

## In-memory registry API (`RunRegistry`)

Use these exports when inspecting active runs or driving custom agent loops into the registry:

| Export                                         | Description                                                                                                                                                                                                                                               |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `registerRun(init, seedAfterId?)`              | Registers a `RunHandle` in process memory. Pass `seedAfterId` (from `lastStreamId()`) when adopting a resumed run so new stream IDs stay strictly greater than previously persisted events.                                                               |
| `getRun(id)`                                   | Returns the local `RunHandle` if hosted by this process, else `undefined`.                                                                                                                                                                                |
| `listRuns()`                                   | Returns all `RunHandle`s currently held in this process.                                                                                                                                                                                                  |
| `listRunsForConversation(conversationId)`      | Returns local runs for a conversation sorted newest first.                                                                                                                                                                                                |
| `publish(run, event)`                          | Mints the next monotonic cursor ID, trims the in-memory ring buffer to `maxStreamLen`, fans out synchronously to live subscribers, and chains Redis `XADD` writes on a per-run serial promise queue so Redis Stream order strictly matches publish order. |
| `pumpRun({ run, agent, trace, log, persist })` | Drains an `AsyncIterable<AgentEvent>` into `publish()` + `trace`, transitions `run.status` (`finished` / `aborted` / `failed`), guarantees `persist()` runs once in `finally`, and schedules memory disposal.                                             |
| `scheduleDisposal(run)`                        | Schedules removal of a settled run from memory after `RUNS_RETAIN_FINISHED_MS` (clamped to Redis stream TTL).                                                                                                                                             |
| `forgetRun(id)`                                | Immediately removes a run handle from process memory.                                                                                                                                                                                                     |

## Low-level Event Store API

When `redis` is configured with an `ioredis` client, these primitives store and tail events in Redis Streams (`run:<runId>:events`). When `redis` is `"memory"` (default), they automatically fall back to an in-process memory event store so single-instance replay and `tailRun()` work identically without Redis.

::field-group
:::field{name="FIRST_ID" type="string" default="'0-0'"}
Sentinel cursor ID meaning "replay from the very first event in the stream".
:::

:::field{name="nextId(prev?)" type="(prev?: string) => string"}
Mints a strictly increasing Redis-compatible `<epochMs>-<seq>` cursor ID.
:::

:::field{name="compareIds(a, b) / firstIndexAfter(ids, afterId)" type="functions"}
Compare stream cursor IDs by `(ms, seq)` and find the first index in `ids` strictly after `afterId`.
:::

:::field{name="streamKey(runId)" type="(runId: string) => string"}
Returns the Redis Stream key for `runId` (`run:<runId>:events`).
:::

:::field{name="appendEvent(runId, id, event)" type="Promise<void>"}
Appends a serialized event to Redis via `XADD` with `MAXLEN ~` trimming and TTL refresh (or to the in-process memory store when `redis` is `"memory"`).
:::

:::field{name="readPage(runId, afterId?, count?)" type="Promise<EventPage>"}
Reads up to `count` stored entries strictly after `afterId` (`FIRST_ID` by default), returning `{ ids, events, lastId }`.
:::

:::field{name="waitForNext(runId, afterId)" type="Promise<EventPage | null>"}
Performs a blocking wait (using `getBlockMs()`, `XREAD BLOCK` in Redis) for new entries after `afterId`, returning an `EventPage` or `null` on timeout.
:::

:::field{name="tailRun(params)" type="() => void"}
Starts replaying historical pages then loops `waitForNext()` until a terminal frame (`done`/`error`), `shouldStop()` returns `true`, or `onIdle()` returns `true`. Returns a synchronous detach callback (does not abort the underlying run).
:::

:::field{name="lastStreamId(runId) / touchStream(runId) / dropStream(runId)" type="Promise helpers"}
Read the latest persisted stream ID (for `seedAfterId` on resume), extend the stream TTL, or delete a stream immediately.
:::
::

## Stream & disconnect invariants

- **Disconnect is not cancellation**: Closing an HTTP/SSE connection (`ReadableStream.cancel()`) detaches the subscriber only — it **never** calls `run.controller.abort()`. The background run continues to completion so the user can refresh the page or reconnect from another tab using `Last-Event-ID`. Only an explicit Stop action (`controller.abort()` + `requestAbort()`) cancels a run.
- **Lossless synchronous replay-before-subscribe**: Inside `streamFromRun()`, buffered frames after `since` are replayed synchronously before attaching the live subscriber callback. Because JavaScript executes synchronously to completion between awaits, no frame can be dropped or duplicated across the replay-to-live handoff.
- **Ordered async persistence without blocking `publish()`**: `publish(run, event)` stays synchronous (matching the agent's `emit` callback), while a per-run serial promise chain sequences Redis `XADD` calls so network jitter can never land a `chunk` frame ahead of the `tool_end` that preceded it. Redis hiccups are swallowed so the live run and local subscribers never fail.
- **Unified monotonic cursor space**: Both local `RunRegistry` and Redis Streams share `<epochMs>-<seq>` IDs minted via `nextId()` (starting from `FIRST_ID = "0-0"`), so a client's `Last-Event-ID` cursor works seamlessly whether reconnects land on the owning replica (`streamFromRun()`) or a sibling replica (`streamFromStore()`).
- **Clamped TTL and blocking windows**: `getBlockMs()` (`RUNS_STREAM_BLOCK_MS`) is clamped to `<= floor(ttlSeconds * 1000 / 2)` so a parked `XREAD BLOCK` cannot outlive the stream key, and `RUNS_RETAIN_FINISHED_MS` is clamped to `<= ttlSeconds * 1000` so in-memory copies never outlive the durable log.
