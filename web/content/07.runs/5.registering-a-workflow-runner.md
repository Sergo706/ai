This walkthrough connects every layer of `@riavzon/ai`'s [Workflow Agents](/workflow-agents) and [Run System](/runs) into one production-ready architecture:

```text [Boot -> Resumer -> Runner -> HTTP Flow]
server boot (boot.ts)
  ├─ 1. await configuration(...)               // DB, Redis, AI clients, logger
  ├─ 2. import "./runs/resumers/*"             // Side-effect registerRunResumer() calls
  └─ 3. const stopRuns = startRuns()           // Reconcile stale leases + start sweeper

POST /api/workflows/product (HTTP Launch)
  └─ workflowStreamWithRegistry()
       └─ runProductResearch()                 // Shared runner wrapping runWorkflow()
            ├─ AgenticWorkflowLoop + ctx.saveCheckpoint(checkpoint(...))
            └─ runProgressFrames() -> RunRegistry + Redis Streams

Process Crash / Deploy / POST /api/runs/:id/retry
  └─ Recovery sweeper or retryRun()
       └─ findRunResumer(row.kind, row.input.name)
            └─ adopt(row) -> runProductResearch({ resumeRunId: row.id, ... })
```

The single most important design rule is **one shared runner function**: both initial HTTP requests and background crash/retry adoptions invoke the exact same runner (`runProductResearch`). The only difference is whether `resumeRunId` is passed.

## Step 1: Define workflow constants & module augmentations

Keep workflow names as shared constants so the runner, resumer, and HTTP handlers can never drift apart. Augment `RunKindRegistry`, `WorkflowNameRegistry`, and `WorkflowAgentRegistry` to get end-to-end TypeScript autocomplete and exhaustiveness checking across `runs.kind`, `runProgressFrames()`, and SSE clients.

```ts [src/workflows/constants.ts]
export const PRODUCT_WORKFLOW = "research-product" as const;
export const TEAM_WORKFLOW = "research-team" as const;

declare module "@riavzon/ai" {
  interface RunKindRegistry {
    // Adds "research" alongside built-in "chat" | "workflow"
    research: true;
  }

  interface WorkflowNameRegistry {
    "research-product": true;
    "research-team": true;
    "deep-research": true;
  }

  interface WorkflowAgentRegistry {
    local_retriever: true;
    web_researcher: true;
    evaluator: true;
    critic: true;
    synthesizer: true;
  }
}
```

::note
When multiple workflows share a single `kind` (such as `"workflow"`), give each one a unique, stable `name`. `findRunResumer(kind, name)` checks for an exact `(kind, name)` match first and falls back to an unnamed resumer registered for `kind` alone.
::

## Step 2: Build the shared durable runner

Wrap your workflow logic in `runWorkflow()`. It owns the entire durable lifecycle: row creation (or atomic claim on `resumeRunId`), lease heartbeats, abort-signal merging (`ctx.leaseSignal`), checkpoint reads/writes, final `partial` storage, and transient-vs-permanent error classification.

```ts [src/runners/productRunner.ts]
import {
  AgenticWorkflowLoop,
  checkpoint,
  getConfiguration,
  parseCheckpoint,
  runWorkflow,
  type Logger,
  type WorkflowCheckpoint,
  type WorkflowPayload,
  type WorkflowProgressEvent,
  type WorkflowStage,
} from "@riavzon/ai";
import { PRODUCT_WORKFLOW } from "../workflows/constants";

export interface ProductResearchOptions {
  query: string;
  productName: string;
  userId?: string;
  conversationId?: number;
  maxRounds?: number;
  signal?: AbortSignal;
  /** Caller-minted runId for SSE streaming (lets the stream register before the DB write). */
  runId?: string;
  /** Existing run ID when adopting an interrupted or retried run. */
  resumeRunId?: string;
  onRunStarted?: (runId: string) => void;
  onProgress?: (event: WorkflowProgressEvent) => void;
}

export interface ProductReport {
  productName: string;
  summary: string;
  sources: string[];
}

const PRODUCT_CHECKPOINT_SPEC = {
  version: 1,
  phases: ["seeds", "local", "external", "critic", "final"] as const,
};

type ProductPhase = (typeof PRODUCT_CHECKPOINT_SPEC.phases)[number];

export async function runProductResearch(
  options: ProductResearchOptions,
  log: Logger = getConfiguration().logger,
): Promise<WorkflowPayload<ProductReport>> {
  const maxRounds = options.maxRounds ?? 3;

  return runWorkflow<ProductReport>(
    {
      kind: "workflow",
      name: PRODUCT_WORKFLOW,
      query: options.query,
      userId: options.userId,
      conversationId: options.conversationId,
      signal: options.signal,
      runId: options.runId,
      resumeRunId: options.resumeRunId,
      onRunStarted: options.onRunStarted,
      onProgress: options.onProgress,
      // Durable snapshot persisted to runs.input so resumers can reconstruct options after a crash.
      // Note: runWorkflow() automatically stamps `name` into runs.input as well.
      input: {
        productName: options.productName,
        maxRounds,
      },
    },
    async (ctx) => {
      // Load prior loop state only when adopting/retrying an existing run
      let resumeFrom: WorkflowCheckpoint | undefined;
      if (options.resumeRunId) {
        const raw = await ctx.loadCheckpoint();
        const saved = parseCheckpoint<WorkflowCheckpoint, ProductPhase>(
          raw,
          PRODUCT_CHECKPOINT_SPEC,
        );
        resumeFrom = saved?.state;
      }

      const loop = new AgenticWorkflowLoop({
        name: PRODUCT_WORKFLOW,
        query: options.query,
        budgets: {
          maxLocalRounds: 3,
          maxExternalRounds: maxRounds,
          localBatchSize: 10,
          maxIntentsPerRound: 3,
          maxTargetsPerIntent: 4,
          maxEvaluatorItems: 20,
          maxConsecutiveInsufficientLocalBatches: 2,
          maxSkippedExternalRounds: 2,
          maxRepeatedIntentRounds: 1,
          maxDiscoveryFailuresPerIntent: 2,
        },
        signal: ctx.leaseSignal,
        resumeFrom,
        onProgress: ctx.emitProgress,
        onCheckpoint: (snapshot) => {
          const phase: WorkflowStage =
            snapshot.completedStages[snapshot.completedStages.length - 1] ??
            "seeds";

          ctx.saveCheckpoint(
            checkpoint({
              phase,
              state: snapshot,
              roundsDone: snapshot.externalRounds,
            }),
          );
        },
        // Supply your adapters: targetExecutor and evaluator are required; localKnowledge, externalDiscovery, critic and finalAnswer are optional.
        // `report` is only set when a finalAnswer adapter is configured.
        ...buildProductAdapters(options.productName),
      });

      const result = await loop.run();

      return {
        source: result.source,
        isSufficient: result.isSufficient,
        stopReason: result.stopReason,
        missingSearchTerms: result.missingIntents,
        urls: result.report?.sources ?? [],
        data: result.report as ProductReport,
      };
    },
    log,
  );
}
```

::tip
Keep `runs.input` minimal and JSON-serializable — store only the parameters needed to re-invoke the runner (`productName`, `maxRounds`, tenant flags), never live objects, callbacks, or large binary blobs.
::

## Step 3: Write defensive resumers

Create one small resumer module per workflow. Each module calls `registerRunResumer()` at top-level import time, defensively narrows `fromJson(row.input)` so rows persisted by older deploys never crash recovery, and delegates straight back into the shared runner with `resumeRunId: row.id`.

### Defensive input deserialization

```ts [src/runs/resumers/workflowInput.ts]
import { fromJson } from "@riavzon/ai";

export interface ProductRunInput {
  productName: string;
  maxRounds?: number;
}

export function parseProductRunInput(
  raw: unknown,
  fallbackQuery: string,
): ProductRunInput {
  const parsed = fromJson<Record<string, unknown>>(raw);
  const productName =
    typeof parsed?.productName === "string" && parsed.productName.trim()
      ? parsed.productName
      : fallbackQuery;
  const maxRounds =
    typeof parsed?.maxRounds === "number" && Number.isInteger(parsed.maxRounds)
      ? parsed.maxRounds
      : undefined;

  return { productName, maxRounds };
}
```

### Registering named vs. single-runner resumers

::tabs
  :::tabs-item{label="Named Workflow (kind + name)" icon="i-lucide-layers"}
  Use `kind: "workflow"` plus a distinct `name` when several workflows share the `"workflow"` kind. If live UI clients can reattach during background recovery, also wire `attachDetachedWorkflow()` + `lastStreamId(row.id)` so recovered progress continues appending to the same Redis Stream.

  ```ts [src/runs/resumers/product.ts]
  import {
    attachDetachedWorkflow,
    getConfiguration,
    lastStreamId,
    registerRunResumer,
    runProgressFrames,
    type ResumableRow,
  } from "@riavzon/ai";
  import { runProductResearch } from "../../runners/productRunner";
  import { PRODUCT_WORKFLOW } from "../../workflows/constants";
  import { parseProductRunInput } from "./workflowInput";

  registerRunResumer({
    kind: "workflow",
    name: PRODUCT_WORKFLOW,
    adopt: async (row: ResumableRow) => {
      const log = getConfiguration().logger;
      const input = parseProductRunInput(row.input, row.query);

      // Keep Redis stream cursor IDs strictly monotonic after frames emitted by the dead replica
      const seedAfterId = await lastStreamId(row.id);
      const detached = attachDetachedWorkflow({
        runId: row.id,
        kind: "workflow",
        conversationId: row.conversation_id ?? undefined,
        seedAfterId,
        log,
      });

      const progress = runProgressFrames(detached.tee(() => {}), {
        query: row.query,
        workflow: PRODUCT_WORKFLOW,
      });

      try {
        const payload = await runProductResearch(
          {
            query: row.query,
            productName: input.productName,
            maxRounds: input.maxRounds,
            userId: row.user_id ?? undefined,
            conversationId: row.conversation_id ?? undefined,
            resumeRunId: row.id,
            signal: detached.run.controller.signal,
            onProgress: progress.onProgress,
          },
          log,
        );

        detached.finish({ type: "product_result", ...payload });
      } catch (err) {
        // Another replica winning the SQL lease race is normal in multi-replica deployments
        if (err instanceof Error && err.message.includes("already owned")) {
          return;
        }
        detached.fail();
        throw err;
      }
    },
  });
  ```
  :::

  :::tabs-item{label="Dedicated Kind (single runner)" icon="i-lucide-compass"}
  If a custom `RunKind` (added via `RunKindRegistry`) maps to exactly one workflow, omit `name` so the resumer matches every row with that `kind`. When background adoption does not need to stream live progress over SSE, simply call the runner without `onProgress`.

  ```ts [src/runs/resumers/research.ts]
  import {
    getConfiguration,
    registerRunResumer,
    type ResumableRow,
  } from "@riavzon/ai";
  import { runDeepResearch } from "../../runners/researchRunner";

  registerRunResumer({
    kind: "research",
    adopt: async (row: ResumableRow) => {
      const log = getConfiguration().logger;
      await runDeepResearch(
        {
          query: row.query,
          userId: row.user_id ?? undefined,
          conversationId: row.conversation_id ?? undefined,
          resumeRunId: row.id,
        },
        log,
      );
    },
  });
  ```
  :::

## Step 4: Wire server boot & graceful shutdown

Initialize `@riavzon/ai` first, side-effect import every resumer module so `findRunResumer()` sees the full table before the first recovery sweep runs, then call `startRuns()` once per process.

```ts [src/boot.ts]
import OpenAI from "openai";
import { Redis } from "ioredis";
import { configuration, startRuns } from "@riavzon/ai";

// Side-effect imports: register every workflow resumer BEFORE startRuns()
import "./runs/resumers/product";
import "./runs/resumers/research";

let stopRuns: (() => void) | undefined;

export async function bootAi(): Promise<void> {
  await configuration({
    db: process.env.DATABASE_URL ?? "./data/ai.sqlite",
    redis: process.env.REDIS_URL ? new Redis(process.env.REDIS_URL) : "memory",
    openAiConfig: new OpenAI({ apiKey: process.env.OPENAI_API_KEY }),
    embeddingConfig: {
      dimensions: 1536,
      retrievalModel: "text-embedding-3-small",
      matchingModel: "text-embedding-3-small",
    },
  });

  // 1. Marks stale leases from dead processes as "interrupted"
  // 2. Starts the periodic recovery sweeper for all registered resumers
  stopRuns = startRuns();
}

export function shutdownAi(): void {
  stopRuns?.();
}

process.on("SIGTERM", () => {
  shutdownAi();
  process.exit(0);
});
```

::callout{icon="i-lucide-shield" color="neutral"}
**Safe rolling deploys:** During a rolling deployment, an older replica may see an abandoned run whose `name` only exists on the new replica. Instead of marking it failed immediately, `startRuns()` leaves unmatched runs alone for `RUNS_UNCLAIMED_GRACE_MS` (default 10 minutes), giving the new replica plenty of time to adopt it.
::

## Step 5: Expose the HTTP endpoints

A complete production API exposes four routes: **launch**, **reattach**, **abort**, and **retry**.

::tabs
  :::tabs-item{label="Launch (JSON + SSE)" icon="i-lucide-play"}
  Mint `runId` before starting the stream so `workflowStreamWithRegistry()` registers the `RunHandle` synchronously and emits live progress frames through `runProgressFrames()`.

  ```ts [src/routes/workflows/product.post.ts]
  import {
    getConfiguration,
    runProgressFrames,
    setSseHeaders,
    workflowStreamWithRegistry,
  } from "@riavzon/ai";
  import { runProductResearch } from "../../runners/productRunner";
  import { PRODUCT_WORKFLOW } from "../../workflows/constants";

  export async function POST(req: Request): Promise<Response> {
    const body = (await req.json()) as {
      query: string;
      productName: string;
      userId?: string;
      conversationId?: number;
      stream?: boolean;
    };

    const log = getConfiguration().logger;

    // Non-streaming JSON mode (still durable in the runs table)
    if (!body.stream) {
      const payload = await runProductResearch(
        {
          query: body.query,
          productName: body.productName,
          userId: body.userId,
          conversationId: body.conversationId,
        },
        log,
      );
      return Response.json(payload);
    }

    // Detached SSE mode: survives client disconnects and supports cross-replica reattach
    const runId = crypto.randomUUID();

    const stream = workflowStreamWithRegistry({
      runId,
      kind: "workflow",
      conversationId: body.conversationId,
      log,
      execute: async ({ emit, signal }) => {
        const progress = runProgressFrames(emit, {
          query: body.query,
          workflow: PRODUCT_WORKFLOW,
        });

        const payload = await runProductResearch(
          {
            query: body.query,
            productName: body.productName,
            userId: body.userId,
            conversationId: body.conversationId,
            runId,
            signal,
            onRunStarted: progress.onRunStarted,
            onProgress: progress.onProgress,
          },
          log,
        );

        return { type: "product_result", ...payload };
      },
      onError: (err) => log.error({ err, runId }, "Product workflow failed"),
    });

    return new Response(stream, { headers: setSseHeaders() });
  }
  ```
  :::

  :::tabs-item{label="Reattach (SSE)" icon="i-lucide-radio-tower"}
  Serve same-process runs straight from memory via `streamFromRun()`, and fall back to Redis Streams via `streamFromStore()` whenever the reconnect lands on another replica.

  ```ts [src/routes/runs/[id]/stream.get.ts]
  import {
    FIRST_ID,
    getConfiguration,
    getRun,
    getRunById,
    setSseHeaders,
    streamFromRun,
    streamFromStore,
  } from "@riavzon/ai";

  export async function GET(
    req: Request,
    { params }: { params: { id: string } },
  ): Promise<Response> {
    const url = new URL(req.url);
    const since =
      req.headers.get("last-event-id") ??
      url.searchParams.get("since") ??
      FIRST_ID;
    const log = getConfiguration().logger;

    // Fast path: run is hosted (or recently settled) in this replica
    const local = getRun(params.id);
    if (local) {
      return new Response(
        streamFromRun({
          run: local,
          since,
          conversationId: local.conversationId,
          runId: local.id,
          log,
        }),
        { headers: setSseHeaders() },
      );
    }

    // Cross-replica path: check SQL status before tailing Redis
    const row = await getRunById(params.id);
    if (!row) {
      return Response.json({ error: "Run not found" }, { status: 404 });
    }
    if (row.status !== "running" && row.status !== "interrupted") {
      return Response.json(
        { error: "Run is no longer active", status: row.status },
        { status: 409 },
      );
    }

    return new Response(
      streamFromStore({
        runId: row.id,
        since,
        conversationId: row.conversation_id ?? undefined,
        log,
        isRunAlive: async () => {
          const latest = await getRunById(row.id);
          return latest?.status === "running" || latest?.status === "interrupted";
        },
      }),
      { headers: setSseHeaders() },
    );
  }
  ```
  :::

  :::tabs-item{label="Abort" icon="i-lucide-square"}
  Always flag `requestAbort(id)` in SQL *and* abort any local `RunHandle` controller so cancellation works regardless of which replica receives the request.

  ```ts [src/routes/runs/[id]/abort.post.ts]
  import { getRun, getRunById, requestAbort } from "@riavzon/ai";

  export async function POST(
    _req: Request,
    { params }: { params: { id: string } },
  ): Promise<Response> {
    const local = getRun(params.id);
    local?.controller.abort();

    const flagged = await requestAbort(params.id);
    if (local || flagged) {
      return Response.json(
        { ok: true, runId: params.id, status: "aborting" },
        { status: 202 },
      );
    }

    const row = await getRunById(params.id);
    if (!row) {
      return Response.json({ error: "Run not found" }, { status: 404 });
    }

    return Response.json({ ok: true, runId: row.id, status: row.status });
  }
  ```
  :::

  :::tabs-item{label="Retry" icon="i-lucide-rotate-cw"}
  Call `retryRun(id)` to reopen an `interrupted`, `aborted`, or `failed` run in place (preserving its saved checkpoint) and hand it back to the registered resumer.

  ```ts [src/routes/runs/[id]/retry.post.ts]
  import { retryRun } from "@riavzon/ai";

  export async function POST(
    _req: Request,
    { params }: { params: { id: string } },
  ): Promise<Response> {
    const outcome = await retryRun(params.id);

    if (!outcome.ok) {
      const status = outcome.reason === "not_found" ? 404 : 409;
      return Response.json(outcome, { status });
    }

    // Client can immediately connect to GET /api/runs/:id/stream to follow the resumed run
    return Response.json(outcome, { status: 202 });
  }
  ```
  :::

## Production checklist

- **Register before boot:** Import every resumer module before calling `startRuns()` so the startup sweep finds all runners immediately.
- **Keep `name` immutable:** Renaming a workflow's `name` orphans in-flight `runs.input.name` rows from prior deploys unless you keep an alias resumer during rollout.
- **Version your checkpoints:** Bump `CHECKPOINT_SPEC.version` whenever `state` changes incompatibly so `parseCheckpoint()` falls back to a clean restart instead of crashing on legacy JSON.
- **Do not abort on HTTP disconnect:** Never wire `req.signal` directly into `runWorkflow()`'s `signal` for detached workflows — pass `workflowStreamWithRegistry()`'s `signal` instead so closing a browser tab does not kill the run.
- **Check `chat` expectations:** Chat agent turns (`kind: "chat"`) are deliberately not auto-resumed by the recovery sweeper; retry failed chat turns from the UI instead.
