Persisting a complete audit trail of how an agent arrived at its answer — and stopping upstream LLM/tool work the instant a user cancels — are essential for reliable AI backends. `@riavzon/ai` provides `TraceCollector` and `createRequestAbort()` for both `createAgent()` and custom loops.

## Recording turns with `TraceCollector`

`TraceCollector` aggregates an agent stream into a compact, JSON-serializable `MessageTrace` object containing `reasoning` rounds and `steps` (tool invocations), alongside the accumulated `fullResponse` text.

```ts [src/trace-basic.ts]
import { TraceCollector } from "@riavzon/ai";

const trace = new TraceCollector();

for await (const event of agentStream) {
  trace.apply(event);
}

console.log("Final assistant text:", trace.fullResponse);
console.log("Stored trace:", trace.toTrace());
// Returns null if no reasoning, tool steps, or extension fields were recorded:
// {
//   reasoning: [{ round: 0, text: "..." }],
//   steps: [{ id: "call_1", name: "calculator", args: {...}, result: "42", ok: true, durationMs: 3 }]
// }
```

### Feeding unredacted tool steps (`addToolStep`)

SSE `tool_end` events only carry redacted previews (or `""` when `emitResult: "none"`). Pass `onToolResult: (step) => trace.addToolStep(step)` to `executeToolLoop()` so `trace.toTrace().steps` captures the exact unredacted model-facing tool outputs required for accurate multi-turn replay in `historyToMessages()`.

## Writing custom `TraceExtension` plugins

Pass one or more `TraceExtension<TExtra>` objects to `new TraceCollector(extensions)` or to `createAgent({ trace: [...] })` to record application-specific metadata (such as visited URLs, workflow stages, token counters, or citations) right onto `ChatTurnResult.trace`.

```ts [src/trace-extension.ts]
import {
  createAgent,
  TraceCollector,
  type AgentEvent,
  type TraceExtension,
} from "@riavzon/ai";

interface MetricsTrace extends Record<string, unknown> {
  toolCount: number;
  failedTools: string[];
}

export function createMetricsExtension(): TraceExtension<MetricsTrace> {
  let toolCount = 0;
  const failedTools: string[] = [];

  return {
    apply(event: AgentEvent) {
      if (event.type === "tool_end") {
        toolCount += 1;
        if (!event.ok) failedTools.push(event.name);
      }
    },
    toTrace() {
      if (toolCount === 0) return undefined;
      return { toolCount, failedTools };
    },
  };
}

// Standalone usage
const collector = new TraceCollector([createMetricsExtension()]);

// Or attached directly to createAgent()
const agent = await createAgent({
  model: { model: "gpt-4o-mini" },
  systemInstructions: "Answer concisely.",
  trace: [createMetricsExtension()],
});
```

::warning
Create a fresh extension instance per turn if you use `TraceCollector` directly. When passing stateful extensions to `createAgent({ trace })`, note that `createAgent()` uses the provided extension instances across turns unless you keep them stateless or reset per turn.
::

## Handling disconnects with `createRequestAbort()`

HTTP frameworks report client disconnects differently (`req.on("close", ...)` in Node/Express, `req.signal.addEventListener("abort", ...)` in Fetch/Next.js/Hono). `createRequestAbort()` wraps an `AbortController` with disconnect logging and a `markFinished()` guard so late socket close events after a completed response never log false-positive cancellations.

```ts [src/abort-control.ts]
import { createRequestAbort, RequestAbortedError } from "@riavzon/ai";

export async function handleNodeRequest(
  req: { on: (event: string, cb: () => void) => void },
  userId: string,
  message: string,
) {
  const abort = createRequestAbort({
    meta: { userId, route: "/api/chat" },
    onDisconnect: (cancel) => {
      req.on("close", cancel);
    },
  });

  try {
    const result = await agent.complete({
      message,
      userId,
      signal: abort.signal,
    });
    abort.markFinished();
    return result;
  } catch (err) {
    if (err instanceof RequestAbortedError) {
      return null;
    }
    throw err;
  }
}
```

### `RequestAbort` methods

::field-group
  :::field{name="signal" type="AbortSignal"}
  Pass directly into `agent.chat({ signal })`, `executeToolLoop({ signal })`, or `AgenticWorkflowLoop({ signal })`.
  :::

  :::field{name="abort()" type="() => void"}
  Programmatically cancels the request unless `markFinished()` has already been called.
  :::

  :::field{name="markFinished()" type="() => void"}
  Marks the turn complete so subsequent HTTP connection-close callbacks become no-ops instead of logging a client disconnect.
  :::
::

### Checking abort errors cleanly (`isAbortError`, `runWasAborted`)

When catching errors across fetch calls, OpenAI SDK requests, and `AbortController` signals, use `isAbortError(err)` or `runWasAborted({ error, signal, leaseAborted })` from `@riavzon/ai` to distinguish cancellation from real failures consistently.
