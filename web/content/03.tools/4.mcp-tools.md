`@riavzon/ai` integrates with remote **Model Context Protocol (MCP)** servers over Streamable HTTP using the optional `@modelcontextprotocol/client` peer dependency. Each tool advertised by an MCP server is automatically converted into an OpenAI `ChatCompletionFunctionTool` definition and a matching `ToolSpec` backed by the live MCP connection.

## Install the MCP peer

```bash [Terminal]
npm install @modelcontextprotocol/client
```

## Connect MCP servers inside `createAgent()`

Add one or more `McpServerConfig` objects to `tools.mcp`. `createAgent()` connects during construction, fetches every server's tool list, applies namespacing and exclusion filters, and exposes the resulting tools alongside your built-in and custom tools.

```ts [src/mcp-agent.ts]
import { createAgent } from "@riavzon/ai";

export const agent = await createAgent({
  model: {
    model: "gpt-4o-mini",
    tools: { maxRounds: 8 },
  },
  systemInstructions:
    "Use connected MCP tools to inspect repositories and docs.",
  tools: {
    common: ["calculator"],
    mcp: [
      {
        namespace: "docs",
        url: "https://mcp.example.com/docs",
        auth: {
          type: "bearer",
          token: async () => await fetchFreshServiceToken(),
        },
        exclude: ["delete_index", "reindex_all"],
        clientInfo: { name: "my-support-app", version: "1.2.0" },
        policy: {
          cache: { ttl: 600 },
          concurrency: 3,
          maxCalls: 10,
          stream: { emitResult: "preview" },
        },
      },
      {
        namespace: "analytics",
        url: "https://mcp.example.com/analytics",
        auth: {
          type: "headers",
          headers: { "X-API-Key": process.env.ANALYTICS_MCP_KEY! },
        },
        exclude: (toolName) => toolName.startsWith("admin_"),
      },
    ],
  },
});

// Always close MCP connections on shutdown
process.on("SIGTERM", async () => {
  await agent.close();
});
```

## `McpServerConfig` options

::field-group
:::field{name="url" type="string | URL" required}
Streamable HTTP endpoint of the MCP server (for example `https://mcp.example.com/mcp`).
:::

:::field{name="namespace" type="string"}
Optional prefix prepended to every tool name from this server using double underscores (`${namespace}__${toolName}`). Unsafe characters outside `[a-zA-Z0-9_-]` are replaced with `_`, and the combined name is truncated to 64 characters to satisfy provider limits.
:::

:::field{name="auth" type="McpAuth" default='{ type: "none" }'}
Authentication strategy for the MCP transport:

- `{ type: "none" }`: unauthenticated connection.
- `{ type: "bearer", token: string | (() => string | Promise<string>) }`: static or dynamically refreshed bearer token.
- `{ type: "headers", headers: Record<string, string> }`: custom HTTP headers sent on requests.
- `{ type: "oauth", provider: AuthProvider | OAuthClientProvider }`: full MCP OAuth client provider.
  :::

:::field{name="exclude" type="readonly string[] | ((toolName: string) => boolean)"}
Drops tools by name or predicate. Matching runs against the **server's original tool name** before `namespace` is prepended.
:::

:::field{name="clientInfo" type="{ name: string; version: string }"}
Client identity advertised during the MCP handshake (defaults to `{ name: "ai", version: "1.0.0" }`).
:::

:::field{name="policy" type="McpToolPolicy"}
Shared `ToolSpec` policy (`cache`, `maxCalls`, `concurrency`, `stream`) inherited by every tool discovered on this server.
:::
::

## How MCP responses and errors are handled

::warning
**Binary MCP returns are omitted and never reach the model.** `@riavzon/ai` extracts only `text` blocks, embedded resources that include a `text` string, and `resource_link` entries. Binary blocks — including `image`, `audio`, and binary `resource.blob` payloads — are skipped. Unless the MCP server also returns `structuredContent` on a successful call, a tool returning only binary blocks gives the model an empty string. Return a text summary, a `resource_link` URL, or `structuredContent` metadata for binary assets.
::

When the model calls an MCP-backed tool:

- **Structured and text results**: `@riavzon/ai` prefers `structuredContent` on successful calls. Otherwise it extracts and joins readable text from `content` blocks (`text`, text resources, and `resource_link` entries) with newlines.
- **Tool errors**: If the MCP server flags an error (`isError: true`) or throws a transport error, the handler returns a `toolError()` envelope (`MCP_TOOL_ERROR` or `MCP_CALL_FAILED`) instead of crashing the turn, and `withToolCache()` skips caching the failed call.
- **Name collisions**: If two MCP servers — or an MCP server and a local tool — claim the same final tool name, `createAgent()` throws at startup. Give each server a distinct `namespace` to avoid collisions.

## Use `createMcpToolset()` in your own AI client

You do not need `createAgent()` to use MCP tools. Call `createMcpToolset()` directly to obtain an `McpToolset` with ready-to-use OpenAI definitions and `ToolSpec[]`, plus live `refresh()` and `close()` hooks.

```ts [src/custom-mcp-client.ts]
import OpenAI from "openai";
import {
  buildToolRegistry,
  createMcpToolset,
  executeToolLoop,
} from "@riavzon/ai";

const mcp = await createMcpToolset([
  {
    namespace: "kb",
    url: "https://mcp.example.com/kb",
    auth: { type: "bearer", token: process.env.KB_TOKEN! },
    policy: { cache: { ttl: 300 }, concurrency: 2 },
  },
]);

try {
  // Re-fetch tool lists in place whenever a server updates its catalog
  await mcp.refresh();

  const registry = buildToolRegistry({ userId: "user_42" }, mcp.specs);
  const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

  const completion = await executeToolLoop({
    client,
    model: "gpt-4o-mini",
    messages: [
      { role: "system", content: "Answer using the knowledge base tools." },
      { role: "user", content: "Find our SLA response times." },
    ],
    availableTools: mcp.definitions,
    handlers: registry.handlers,
    tools: { temperature: 0.1, maxTokens: 2048, maxRounds: 5 },
    chat: { temperature: 0.3, maxTokens: 4096 },
    toolConcurrency: registry.toolConcurrency,
    toolStreaming: registry.toolStreaming,
  });

  console.log(completion.choices[0]?.message?.content);
} finally {
  // Safe to call multiple times
  await mcp.close();
}
```

::tip
`mcp.refresh()` mutates `mcp.definitions` and `mcp.specs` **in place**, so references held by your application automatically observe updated tool lists after refresh without re-allocating your wiring.
::
