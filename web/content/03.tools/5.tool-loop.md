`executeToolLoop()` is the core execution engine underneath `createAgent()`. If you maintain your own conversation store, prompt builder, or custom AI client, call `executeToolLoop()` directly — it does not require `configuration()`, a database, or Redis (unless your handlers themselves use them).

## Two execution overloads

`executeToolLoop()` exposes two overloads controlled by the `stream` flag:

- **`stream: true`**: returns an `AsyncGenerator<AgentEvent>` yielding `reasoning`, `tool_start`, `tool_end`, `chunk`, and `error` events in real time.
- **`stream?: false`**: resolves with the final OpenAI `ChatCompletion` object once the model produces its final answer.

::tabs
  :::tabs-item{label="Streaming (AsyncGenerator<AgentEvent>)" icon="i-lucide-radio"}
  ```ts [src/low-level-stream.ts]
  import OpenAI from "openai";
  import {
    executeToolLoop,
    RequestAbortedError,
    toolError,
    type StoredToolStep,
  } from "@riavzon/ai";

  const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });
  const controller = new AbortController();
  const recordedSteps: StoredToolStep[] = [];

  try {
    for await (const event of executeToolLoop({
      client,
      model: "gpt-4o-mini",
      stream: true,
      signal: controller.signal,
      thinkingEffort: "medium",
      messages: [
        { role: "system", content: "Use tools to answer accurately." },
        { role: "user", content: "Check inventory for SKU-100 and SKU-200." },
      ],
      availableTools: [
        {
          type: "function",
          function: {
            name: "check_inventory",
            description: "Check stock level for a SKU.",
            parameters: {
              type: "object",
              properties: { sku: { type: "string" } },
              required: ["sku"],
            },
          },
        },
      ],
      handlers: {
        check_inventory: async ({ sku }) => {
          if (typeof sku !== "string") return toolError("INVALID_SKU", "SKU is required");
          return { sku, inStock: 42 };
        },
      },
      tools: {
        temperature: 0.1,
        maxTokens: 2048,
        maxRounds: 5,
        maxCalls: 15,
      },
      chat: {
        temperature: 0.4,
        maxTokens: 4096,
      },
      toolConcurrency: {
        check_inventory: 2,
      },
      toolStreaming: {
        check_inventory: { emitArgs: true, emitResult: "preview" },
      },
      onToolResult: (step) => {
        recordedSteps.push(step);
      },
    })) {
      switch (event.type) {
        case "reasoning":
          process.stderr.write(event.delta);
          break;
        case "tool_start":
          console.log(`[tool_start] ${event.name} (${event.callIndex}/${event.callTotal})`);
          break;
        case "tool_end":
          console.log(`[tool_end] ${event.name} ok=${event.ok} ${event.durationMs}ms`);
          break;
        case "chunk":
          process.stdout.write(event.text);
          break;
      }
    }
  } catch (err) {
    if (err instanceof RequestAbortedError) {
      console.log("Turn aborted cleanly.");
    } else {
      throw err;
    }
  }
  ```
  :::

  ```ts [src/low-level-complete.ts]
  import OpenAI from "openai";
  import { executeToolLoop } from "@riavzon/ai";

  const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

  const completion = await executeToolLoop({
    client,
    model: "gpt-4o-mini",
    messages: [
      { role: "system", content: "Return concise answers." },
      { role: "user", content: "Check inventory for SKU-100." },
    ],
    availableTools: [/* ChatCompletionTool[] */],
    executor: async (name, args, ctx) => {
      // Single dispatcher alternative to `handlers`
      return { tool: name, args, callIndex: ctx.callIndex };
    },
    tools: { temperature: 0.1, maxTokens: 2048, maxRounds: 4, maxCalls: 10 },
    chat: { temperature: 0.3, maxTokens: 4096 },
  });

  console.log(completion.choices[0]?.message?.content);
  ```

## `ToolLoopOptions` reference

::field-group
  :::field{name="client" type="ToolLoopClient" required}
  Any OpenAI-compatible client implementing `client.chat.completions.create`.
  :::

  :::field{name="model" type="string" required}
  Model identifier forwarded on every provider call.
  :::

  :::field{name="messages" type="readonly ChatCompletionMessageParam[]" required}
  Full message array including your system prompt and history. Never mutated in place.
  :::

  :::field{name="availableTools" type="readonly ChatCompletionTool[]" required}
  Tool schemas offered during tool rounds. Pass `[]` to skip tool rounds and run a single answer call.
  :::

  :::field{name="handlers | executor" type="Record<string, ToolHandler> | ToolExecutor" required}
  Supply **either** a keyed `handlers` map **or** a single `executor(name, args, ctx)` dispatcher — never both.
  :::

  :::field{name="tools" type="{ temperature: number; maxTokens: number; maxRounds?: number; maxCalls?: number }" required}
  Sampling and safety budgets for tool rounds (`maxRounds` defaults to `5`, `maxCalls` defaults to `20`). Setting `maxRounds: 0` disables tools completely.
  :::

  :::field{name="chat" type="{ temperature: number; maxTokens: number }" required}
  Sampling settings for the final synthesis call when budgets are exhausted or no tools are configured.
  :::

  :::field{name="stream" type="boolean" default="false"}
  Enables streaming mode returning `AsyncGenerator<AgentEvent>`.
  :::

  :::field{name="signal" type="AbortSignal"}
  Aborts in-flight provider calls and tool handlers, throwing `RequestAbortedError`.
  :::

  :::field{name="toolConcurrency" type="Readonly<Record<string, number>>"}
  Per-tool parallel execution caps when the model emits multiple calls in one round. Each tool gets its own concurrency bucket so a slow tool with `concurrency: 1` never blocks fast sibling tools.
  :::

  :::field{name="toolStreaming" type="Readonly<Record<string, ToolStreamPolicy>>"}
  Per-tool SSE disclosure policy (`emitArgs`, `emitResult`, `maxCalls`, `serializeForModel`).
  :::

  :::field{name="emit" type="AgentEventEmitter"}
  Optional callback that mirrors emitted `AgentEvent`s (useful in non-streaming mode or when bridging to an `EventSink`).
  :::

  :::field{name="onToolResult" type="(step: StoredToolStep) => void"}
  Receives every completed tool step with its unredacted model-facing `result`, `args`, `ok`, and `durationMs` so you can save it into `TraceCollector.addToolStep()`.
  :::

  :::field{name="thinkingEffort" type='"low" | "medium" | "high" | "max"'}
  Forwarded to OpenAI-compatible reasoning models as `reasoning_effort` without injecting provider-specific non-standard keys.
  :::

  :::field{name="body" type="ModelBodyOptions"}
  Extra OpenAI request body fields (`top_p`, `presence_penalty`, `frequency_penalty`, `stop`, `seed`, `response_format`, `parallel_tool_calls`, `verbosity`, `service_tier`) forwarded untouched on provider calls.
  :::
::

## Built-in loop guarantees

- **Natural finish detection**: When a tool round returns text without `tool_calls`, `executeToolLoop()` streams or returns that answer immediately without wasting an extra final LLM call.
- **Budget exhaustion fallback**: If the model hits `tools.maxRounds` or `tools.maxCalls`, the loop stops executing tools and makes one final synthesis call without tools using `chat.temperature` and `chat.maxTokens`.
- **Safe error masking**: Provider errors can be masked for end users with `responseUnavailableError()`, which returns a generic error message without leaking internal upstream error bodies.
- **Cancellation safety**: Passing `signal` checks abort state between rounds, cancels in-flight OpenAI streams, and forwards `signal` to every tool's `ToolExecutionContext`.
