A `ToolSpec<TMeta>` describes a tool once — its OpenAI JSON Schema definition, per-request factory, caching policy, call limit, concurrency width, and SSE streaming policy. You can pass `ToolSpec[]` to `createAgent({ tools: { specs } })` or compile them yourself with `buildToolRegistry()`.

## Anatomy of a `ToolSpec`

```ts [src/tools/crmLookup.ts]
import { z } from "zod";
import { jsonToMarkdown, toolError, type ToolSpec } from "@riavzon/ai";

interface AppMeta {
  orgId: string;
  crmToken: string;
}

const crmArgsSchema = z.object({
  email: z.string().email(),
  includeTickets: z.boolean().default(false),
});

export const lookupCustomerSpec: ToolSpec<AppMeta> = {
  name: "lookup_customer",
  definitions: {
    type: "function",
    function: {
      name: "lookup_customer",
      description: "Look up a customer profile and recent support tickets by email.",
      parameters: z.toJSONSchema(crmArgsSchema, { io: "input" }),
    },
  },
  cache: {
    ttl: 300,
    scoped: true,
    normalizeArgs: (args) => ({
      ...args,
      email: typeof args.email === "string" ? args.email.trim().toLowerCase() : args.email,
    }),
  },
  maxCalls: 4,
  concurrency: 2,
  stream: {
    emitArgs: true,
    emitResult: "none",
    serializeForModel: (result) => jsonToMarkdown(result, { maxDepth: 4 }),
  },
  make: (ctx) => async (rawArgs, exec) => {
    const parsed = crmArgsSchema.safeParse(rawArgs);
    if (!parsed.success) {
      return toolError("VALIDATION_ERROR", JSON.stringify(parsed.error.issues));
    }

    const res = await fetch(
      `https://crm.internal/orgs/${ctx.meta?.orgId}/customers?email=${encodeURIComponent(parsed.data.email)}`,
      {
        headers: { Authorization: `Bearer ${ctx.meta?.crmToken}` },
        signal: exec.signal,
      },
    );

    if (res.status === 404) {
      return toolError("NOT_FOUND", `No customer found for ${parsed.data.email}`);
    }
    if (!res.ok) {
      return toolError("CRM_ERROR", `CRM responded with HTTP ${res.status}`);
    }

    return await res.json();
  },
};
```

## `ToolSpec` properties

::field-group
  :::field{name="name" type="string" required}
  Unique tool name matching `definitions.function.name`. Used as the cache key prefix, concurrency bucket key, and `toolsUsed` identifier.
  :::

  :::field{name="definitions" type="ChatCompletionTool" required}
  Standard OpenAI tool definition passed verbatim to `chat.completions.create`. Use Zod 4's `z.toJSONSchema(schema, { io: "input" })` or a plain JSON Schema object.
  :::

  :::field{name="make" type="(ctx: ToolFactoryContext<TMeta>) => ToolHandler" required}
  Factory invoked once per request with `{ userId, conversationId, meta }`. Return a handler `(args, execContext) => unknown`.
  :::

  :::field{name="cache" type="{ ttl: number; scoped?: boolean; normalizeArgs?: (a) => Record<string, unknown> }"}
  Caches non-error results for `ttl` seconds. When `scoped: true`, keys include `ctx.userId`; otherwise the scope is `"global"`. Use `normalizeArgs` to canonicalize casing or strip volatile fields.
  :::

  :::field{name="maxCalls" type="number"}
  Caps invocations of this specific tool per request. Exceeding the cap returns `TOOL_LIMIT_REACHED` instead of running the handler. Also populates `callTotal` in `tool_start`/`tool_end` events.
  :::

  :::field{name="concurrency" type="number"}
  Limits how many parallel calls to this tool execute at once when the model emits multiple tool calls in the same round.
  :::

  :::field{name="stream" type="ToolStreamPolicy"}
  Controls SSE visibility (`emitArgs`, `emitResult: "full" | "preview" | "none"`) and optional model formatting (`serializeForModel`).
  :::
::

## `ToolExecutionContext` inside your handler

Every handler receives `(args, context)` where `context` provides live turn metadata:

- **`context.toolCallId`**: provider ID of this tool call.
- **`context.signal`**: `AbortSignal` for the active turn — forward it to `fetch()`, database queries, or child work so clicking Stop actually cancels long-running I/O.
- **`context.callIndex`** / **`context.callTotal`**: 1-based ordinal and planned total for this tool in the request.
- **`context.emit`**: optional `AgentEventEmitter` for emitting live progress events from inside a long-running tool.

## Returning structured errors with `toolError()`

Never throw raw exceptions for expected domain failures (missing records, validation errors, rate limits). Return `toolError(code, message)` instead:

```ts [src/tools/error-example.ts]
import { toolError } from "@riavzon/ai";

// Produces: '{"error":{"code":"NOT_FOUND","message":"Order ORD-99 does not exist"}}'
return toolError("NOT_FOUND", "Order ORD-99 does not exist");
```

The tool loop recognizes `{"error":...}` strings automatically:

1. Sets `ok: false` on the emitted `tool_end` SSE event.
2. Skips writing the result into `withToolCache()` so transient failures are never cached.
3. Passes the error envelope cleanly back to the model as a `tool` message so the model can recover or ask the user to clarify.

## Controlling SSE disclosure and model formatting (`ToolStreamPolicy`)

`ToolStreamPolicy` decouples what the **model** sees from what the **browser SSE stream** sees:

- **`emitArgs`** *(default `true`)*: set `false` to omit sensitive arguments from `tool_start` SSE frames.
- **`emitResult`** *(default `"preview"`)*:
  - `"full"`: sends the entire serialized tool output in `tool_end.preview`.
  - `"preview"`: truncates `tool_end.preview` at 300 characters.
  - `"none"`: sends `""` in `tool_end.preview` (keeping `tool_start`/`tool_end` UI spinners without leaking large or internal payloads to the client).
- **`serializeForModel`**: transforms non-string handler return values before sending them to the LLM (for example `jsonToMarkdown(result)` to save tokens). Strings returned by handlers bypass `serializeForModel` so `toolError()` envelopes stay intact.

::note
`onToolResult` (used to build persisted `messages.trace`) always receives the full model-facing result rather than the redacted SSE preview, so future conversation turns can replay real tool results.
::

## Low-level registry and wrappers for custom AI clients

If you build your own loop or manage tools outside `createAgent()`, you can use `buildToolRegistry()` or individual wrappers (`withToolCache()`, `limitTool()`, `trackTool()`) directly:

```ts [src/custom-registry.ts]
import {
  buildToolRegistry,
  limitTool,
  trackTool,
  withToolCache,
  type ToolHandler,
} from "@riavzon/ai";

// Option 1: Build a complete registry from ToolSpec[]
const registry = buildToolRegistry(
  { userId: "user_42", conversationId: 12, meta: { orgId: "acme" } },
  [lookupCustomerSpec],
);

console.log(Object.values(registry.definitions)); // ChatCompletionTool[]
console.log(registry.handlers);                   // Record<string, ToolHandler>
console.log(registry.toolConcurrency);            // Record<string, number>
console.log(registry.toolStreaming);              // Record<string, ToolStreamPolicy>
console.log(registry.usedTools);                  // ReadonlySet<string> (filled as tools run)

// Option 2: Compose individual wrappers manually around any ToolHandler
const counts = new Map<string, number>();
const used = new Set<string>();

const rawWeather: ToolHandler = async ({ city }) => ({
  city: String(city),
  tempC: 21,
});

const wrappedWeather = trackTool(
  "get_weather",
  withToolCache(
    "get_weather",
    limitTool("get_weather", 3, rawWeather, counts),
    600,
    "user_42",
  ),
  used,
);
```
