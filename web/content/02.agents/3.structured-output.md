`@riavzon/ai` supports two structured-output modes on every agent turn: **raw JSON mode** (zero extra calls, stream-compatible) and **validated schema mode** (Zod validation plus automatic repair calls backed by `llmSchemaParser()`).

## Mode 1: Raw JSON mode (streaming compatible)

Pass `json: {}` (or `{ validate: false }`) to set `response_format: { type: "json_object" }` on the provider request. The turn still streams chunks normally, makes no extra validation calls, and returns the raw JSON string in `result.text`.

```ts [src/raw-json.ts]
import { createAgent } from "@riavzon/ai";

const agent = await createAgent({
  model: { model: "gpt-4o-mini" },
  systemInstructions:
    "Always reply with valid JSON containing keys: sentiment, tags.",
});

const result = await agent.complete({
  message:
    "The onboarding flow was fast, though billing settings were hard to find.",
  json: {},
});

const parsed = JSON.parse(result.text);
console.log(parsed);
```

::tip
When using raw JSON mode (`response_format: { type: "json_object" }`), OpenAI-compatible providers require your system or user message to explicitly mention JSON.
::

## Mode 2: Zod-validated structured output with repair

Pass `json: { validate: true, schema }` to validate the model's answer against a Zod schema and receive the strongly typed output on `result.structured`.

```ts [src/validated-json.ts]
import { z } from "zod";
import { createAgent } from "@riavzon/ai";

const InvoiceExtractionSchema = z.object({
  vendor: z.string(),
  invoiceNumber: z.string(),
  currency: z.string().length(3),
  totalAmount: z.number(),
  lineItems: z.array(
    z.object({
      description: z.string(),
      quantity: z.number().int().positive(),
      unitPrice: z.number(),
    }),
  ),
});

const agent = await createAgent({
  model: { model: "gpt-4o-mini", temperature: 0.1 },
  systemInstructions:
    "Extract structured invoice details accurately from user text.",
  tools: {
    common: ["calculator"],
  },
});

const result = await agent.complete({
  message:
    "Invoice #INV-2026-09 from Acme Cloud Corp: 3x Pro Seats at $29 USD and 1x Support Add-on at $50 USD.",
  json: {
    validate: true,
    schema: InvoiceExtractionSchema,
    schemaName: "invoice_extraction",
    maxRetries: 2,
    includeSchemaInPrompt: true,
  },
});

if (result.structured) {
  // Fully typed as z.output<typeof InvoiceExtractionSchema>
  console.log(result.structured.vendor, result.structured.totalAmount);
}
```

### How validated mode works

1. Tools still run normally across tool rounds in non-streaming JSON mode (`response_format: { type: "json_object" }`).
2. Before parsing JSON, `@riavzon/ai` strips `<think>...</think>` blocks and Markdown code fences.
3. If JSON parsing or Zod validation fails, `llmSchemaParser()` sends a targeted repair message containing the exact validation errors. When the schema can be converted to JSON Schema, it also attaches structured `response_format` and embeds the schema in the prompt (unless `includeSchemaInPrompt` is `false`).
4. If the schema uses Zod constructs that cannot be converted to a provider JSON Schema, `llmSchemaParser()` logs a warning and retries using the validation error feedback alone.

::warning
Validated schema mode cannot stream partial text tokens because the full answer must pass Zod validation before returning. Unlike streaming turns (which emit an `error` frame and resolve `result.error`), validated JSON turns mark any active durable run `aborted` or `failed` and **rethrow** on failure so you never receive unvalidated data typed as a valid object.
::

### Exact prompts used in validated JSON mode

**Initial pass (`json: { validate: true, schema }`):**

- Runs the tool loop in non-streaming JSON mode (`response_format: { type: "json_object" }`).
- **No extra schema prompt is injected on the initial pass.** Mention JSON (and the expected shape if needed) in your `systemInstructions` or user message, as OpenAI-compatible providers require `"json"` in the prompt when JSON mode is active.
- If the initial tool loop exhausts its tool budgets or has no tools configured, `executeToolLoop()` still appends its trailing synthesis system message (see [Injected prompts and error messages](/tools/tool-loop#injected-prompts-and-error-messages)).

**Repair retries (`llmSchemaParser()`):**

When JSON parsing or Zod validation fails and retries remain, `llmSchemaParser()` retries from your base messages (your system instructions, history, and user prompt — without replaying intermediate tool calls or attaching `tools`), appends the cleaned invalid assistant reply (when non-empty), and appends this `user` repair message:

```text [Exact user repair message sent by llmSchemaParser()]
Your previous response failed JSON/schema validation.
Validation errors: <feedback>
Return the complete corrected JSON matching the supplied schema.
Preserve evidence-grounded content; do not invent missing facts.
Correct required fields, types, and nesting. Remove forbidden keys.
Return only JSON, without markdown or commentary.
Schema: <rendered JSON schema>
```

- `<feedback>` is a JSON array of `{ path, code, message }` issues for Zod failures, `"Response is not valid JSON."` for syntax errors, or the error message when the model returned an empty answer.
- The final `Schema:` line is included only when `includeSchemaInPrompt` is `true` (default) and your Zod schema converts to a provider JSON Schema.

## `JsonOptions` reference

::field-group
:::field{name="validate" type="boolean" default="false"}
When `false` or omitted, sends `response_format: { type: "json_object" }` and leaves parsing to the caller. When `true`, validates against `schema` and populates `ChatTurnResult.structured`.
:::

:::field{name="schema" type="z.ZodType"}
Required when `validate` is `true`. Its inferred output type flows automatically to `ChatTurnResult<z.output<S>>.structured`.
:::

:::field{name="schemaName" type="string" default="results"}
Schema identifier passed to `zodResponseFormat()` and repair prompts.
:::

:::field{name="maxRetries" type="number" default="2"}
Maximum repair calls attempted after the initial model reply fails parsing or schema validation. Set `0` to fail immediately on invalid output.
:::

:::field{name="includeSchemaInPrompt" type="boolean" default="true"}
Includes the rendered JSON Schema inside each repair message. Set `false` for very large schemas already included in your system prompt.
:::
::

## Standalone usage in custom AI clients (`llmSchemaParser`)

If you call OpenAI (or any OpenAI-compatible SDK) directly without `createAgent()`, import `llmSchemaParser()` directly. It accepts any `ChatCompletion` and a `retry` callback so you keep full control over client, model, and request options.

```ts [src/custom-schema-parser.ts]
import OpenAI from "openai";
import { z } from "zod";
import { llmSchemaParser } from "@riavzon/ai";

const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

const SummarySchema = z.object({
  headline: z.string(),
  keyPoints: z.array(z.string()).min(1).max(5),
  confidence: z.number().min(0).max(1),
});

const messages: OpenAI.ChatCompletionMessageParam[] = [
  {
    role: "system",
    content: "Return a JSON summary matching the requested fields.",
  },
  { role: "user", content: "Summarize the release notes for v2.4..." },
];

const initial = await client.chat.completions.create({
  model: "gpt-4o-mini",
  messages,
});

const data = await llmSchemaParser(SummarySchema, initial, {
  agent: "release-summarizer",
  messages,
  schemaName: "release_summary",
  maxRetries: 2,
  retry: (request) =>
    client.chat.completions.create({
      model: "gpt-4o-mini",
      temperature: 0,
      ...request,
    }),
});

console.log(data.headline, data.keyPoints);
```

See [Schema & Text Utilities](/utilities/schema-and-text) for full details on `llmSchemaParser()`, `removeThinking()`, and `removeCodeFence()`.
