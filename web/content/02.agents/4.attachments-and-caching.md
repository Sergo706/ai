`@riavzon/ai` handles two common production needs out of the box: extracting readable Markdown from user-uploaded files on a turn, and short-circuiting near-identical repeated questions using vector similarity over recent exchanges.

## File attachments

Pass browser or Node.js `File` objects in `input.files` on `agent.chat()` or `agent.complete()`. `@riavzon/ai` extracts readable text from supported files with `parseFiles()` and adds that text to the turn's user prompt without saving raw binaries to the database.

::warning
**Binary files are not supported.** `parseFiles()` rejects images (`image/*`), audio (`audio/*`), video (`video/*`), archives, Word documents (`.docx`), and other binary files. `@riavzon/ai` never sends raw bytes, base64 blobs, or multimodal image/file parts to the model — even for PDFs and `.xlsx` spreadsheets, only extracted text or Markdown is sent. Scanned, image-only PDFs yield little or no text, and adding a binary MIME type to `attachments.mimeTypes` only decodes it as UTF-8 text.
::

Supported formats by default:

- **PDF** (`application/pdf`): extracts plain text and document metadata up to `maxPdfPages` (requires `pdf-parse`).
- **CSV** (`text/csv`): converts rows into a Markdown table (requires optional peer `exceljs`).
- **XLSX** (`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`): converts each worksheet into a Markdown table (requires optional peer `exceljs`).
- **Any `text/*` MIME type** (and custom entries in `attachments.mimeTypes`): reads UTF-8 text directly (`text/plain`, `text/markdown`, `text/html`, and similar).

### Exact prompt format injected for attached files

When files are attached, `parseFiles()` wraps each file in `--- START FILE: <fileName> ---` / `--- END FILE ---` delimiters, prepends `[USER UPLOADED FILES FOR CONTEXT]`, and appends `[USER MESSAGE]` followed by your original `input.message`:

```text [Exact user message content sent to the model]
[USER UPLOADED FILES FOR CONTEXT]
--- START FILE: costs.csv ---
<extracted text or Markdown from costs.csv>
--- END FILE ---

--- START FILE: notes.txt ---
<extracted UTF-8 text from notes.txt>
--- END FILE ---

[USER MESSAGE]
What is the total cost in this CSV?
```

::note
When `conversation: { persist: true }` is enabled, `createAgent()` saves this exact combined string (including the extracted file blocks) as the user message in the `messages` table so later turns in the thread retain the file context. The embedding stored for that user message is computed from the raw `input.message` without file contents, and semantic cache lookup is bypassed on turns with files.
::

### Configuring attachment limits

Override default file limits in `AgentConfig.attachments`:

```ts [src/agent-attachments.ts]
import { createAgent } from "@riavzon/ai";

const agent = await createAgent({
  model: { model: "gpt-4o-mini" },
  systemInstructions: "Analyze attached documents carefully and cite figures.",
  attachments: {
    maxFiles: 3,
    maxBytes: 10 * 1024 * 1024, // 10 MB
    maxPdfPages: 5,
    mimeTypes: [
      "application/pdf",
      "text/csv",
      "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
    ],
  },
});

const file = new File(["item,amount\nHosting,120\nDomain,15\n"], "costs.csv", {
  type: "text/csv",
});

const result = await agent.complete({
  message: "What is the total cost in this CSV?",
  files: [file],
});
```

::field-group
:::field{name="maxFiles" type="number" default="3"}
Maximum number of files accepted on one turn.
:::

:::field{name="maxBytes" type="number" default="10485760"}
Maximum size per file in bytes (10 MB default).
:::

:::field{name="mimeTypes" type="readonly string[]"}
Allowed non-`text/*` MIME types. Any `text/*` MIME type is always accepted alongside this list.
:::

:::field{name="maxPdfPages" type="number" default="5"}
Maximum PDF pages extracted before truncating.
:::
::

### Request validation schemas (`askSchema`, `fileUploadSchema`)

If you want Zod request validation matching these attachment defaults in your HTTP route handler, `@riavzon/ai` exports `fileUploadSchema`, `whoIsUser`, and `askSchema` directly:

```ts [src/routes/ask.ts]
import { askSchema } from "@riavzon/ai";

const parsed = askSchema.safeParse({
  currentMessage: "Summarize this PDF.",
  files: uploadedFiles,
  user: { locale: "en-US", timezone: "UTC" },
});
```

## Semantic caching

When many users ask identical or near-identical questions (such as FAQ lookups or static policy explanations), semantic caching skips the LLM round-trip by embedding the prompt once with `generateMatchingEmbedding()` (`embeddingConfig.matchingModel`), finding a recent user message with cosine similarity at or above `similarity`, and replaying its stored assistant answer.

```ts [src/cached-agent.ts]
import { createAgent } from "@riavzon/ai";

const agent = await createAgent({
  model: { model: "gpt-4o-mini" },
  systemInstructions: "Answer product questions clearly.",
  conversation: { persist: true },
  tools: {
    common: ["get_current_datetime", "currencies_convertor", "search_db"],
  },
  semanticCache: {
    similarity: 0.92,
    windowHours: 24,
    poisonTools: ["get_current_datetime", "currencies_convertor"],
    skipEvaluator: (_conversationId, message) => message.includes("latest"),
  },
});
```

### How semantic cache safety works

1. **Tenant isolation**: Cache lookups are scoped by `userId` when provided so users never receive another user's private answer.
2. **Poison tools**: If the matched earlier reply invoked any tool in `poisonTools` (such as live time or exchange-rate lookups), the match is skipped and the model runs fresh.
3. **Per-turn bypass**: Return `true` from `skipEvaluator(conversationId, message)` to bypass the cache on specific requests (for example, a "Regenerate" button).
4. **Transcript consistency**: On a cache hit, `@riavzon/ai` still saves the user prompt and cached assistant reply to `messages` and sets `ChatTurnResult.cached` to `true`.
5. **Automatic bypass with attachments**: Turns carrying `files` always skip the semantic cache because the answer depends on the attached files.
6. **Full run-backed cache hits**: When both `runs` and `semanticCache` are enabled, a cache hit still creates a finished `runs` row, publishes the `chunk` and `done` frames to the event store, and returns both `runId` and `cached: true`. Reconnecting clients calling `streamFromRun()`, `streamFromStore()`, or `getRunById()` work identically for cached and live turns.

::field-group
:::field{name="similarity" type="number" default="0.9"}
Minimum cosine similarity (0 to 1) required for an earlier question to count as a match.
:::

:::field{name="windowHours" type="number" default="24"}
Lookback window in hours for candidate stored messages.
:::

:::field{name="poisonTools" type="readonly string[]"}
Tool names whose presence in an earlier reply's `tools_used` disqualifies that cached reply.
:::

:::field{name="skipEvaluator" type="(conversationId: number, message: string) => boolean"}
Optional callback that returns `true` to skip the semantic cache for a turn.
:::
::

## Low-level usage in custom AI clients

You can call `parseFiles()`, `tryCachedReply()`, and `checkChatSemanticCache()` directly without `createAgent()`:

```ts [src/custom-attachments-cache.ts]
import {
  generateMatchingEmbedding,
  getConfiguration,
  parseFiles,
  tryCachedReply,
} from "@riavzon/ai";

export async function preprocessTurn(
  convId: number,
  userId: string,
  rawMessage: string,
  files?: File[],
) {
  const { message, hasFiles } = await parseFiles(files, rawMessage, {
    maxFiles: 2,
    maxPdfPages: 10,
  });

  if (!hasFiles) {
    const embedding = await generateMatchingEmbedding(message);
    const cachedStream = await tryCachedReply(["get_current_datetime"], {
      convId,
      userId,
      message,
      embedding,
      log: getConfiguration().logger,
      stream: true,
      similarity: 0.92,
      cacheWindowHours: 24,
    });

    if (cachedStream instanceof ReadableStream) {
      return { cachedStream, message };
    }
  }

  return { cachedStream: null, message };
}
```
